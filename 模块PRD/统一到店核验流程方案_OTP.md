# 统一到店核验流程方案（OTP + SMS H5 链接）

> 目标：合并线上预约和直接到店两条路径为一个统一流程  
> 方式：OTP 验证身份 + SMS 同时送达 H5 报告跟踪链接  
> 效果：不再需要口头确认、不再需要平板扫码、不再需要 H5 授权页

---

## 一、当前问题

| 维度 | 线上预约 | 直接到店 | 问题 |
|------|----------|----------|------|
| 平板入口 | "查询预约"按钮 | "生成二维码"按钮 | 两个入口，店员需判断 |
| 用户操作 | 零操作 | 扫码 + 点 H5 同意 | 不一致 |
| 等待时间 | 即时 | 等用户扫码 10-30 秒 | 体验落差 |
| 身份验证 | 口头确认姓名 | H5 点击同意 | 强度不同 |
| H5 获取方式 | 无（App 内查看）| 平板扫码 | 不可靠（反光/光线差/摄像头差）|
| 预填信息 | 有旧机自填+初步估价 | 无 | 质检时信息不对等 |

根因：**线上预约在 App 内完成了注册和授权，直接到店没有。**

---

## 二、统一方案

### 核心思路

不管用户是否预约，店员到店都走**同一套流程**：

```
手机号 → 发送 SMS（含 OTP + H5 链接）→ 店员输入 OTP 验证 → 身份确认 → 质检 → 用户点 H5 链接查看报告
```

一条 SMS 同时送达两样东西：**OTP（店员用来验证身份）+ H5 短链（用户用来跟踪报告和接受报价）**。

预约信息和旧机自填数据作为**预填辅助信息**展示在平板上，不改变流程主干。

## 三、两条路径对比（统一后）

```

               │

               │
        系统验证 OTP ✅
               │
         身份确认（统一的验证方式）
               │

     │                   │

     │                   │

               │

               │

               │
        用户接受报价 → H5/App 点击 → 核销流程
```

## 四、关键设计决策

### 4.1 OTP 设计

| 设计点 | 方案 | 说明 |
|--------|------|------|
| OTP 长度 | 6 位数字 | 印度标准 |
| 有效期 | 3 分钟 | 过期需重新发送 |
| 发送渠道 | SMS（优先）+ WhatsApp Business API（备选） | 印度 WhatsApp 渗透率高 |
| 发送方 ID | 平台品牌名（如 "BOTT-OTP"） | 避免被误判为垃圾短信 |
| 重试次数 | 最多 3 次 | 超过后 60 秒冷却 |
| 重发冷却 | 60 秒 | 防止恶意刷 OTP |
| 每日上限 | 同一手机号每天最多 5 次 | 防止滥用 |

### 4.2 SMS 模板

```
[Platform Name] OTP: 123456
Track your inspection: https://bott.in/s/abc123
Valid for 3 minutes. Do not share this message.
आपका OTP: 123456। निरीक्षण ट्रैक करें: https://bott.in/s/abc123
```

### 4.3 H5 页面状态

| 阶段 | H5 展示内容 |
|------|-------------|
| OTP 验证后（质检前） | "正在准备检测您的设备... Preparing to inspect your device..." |
| 质检中 | "正在检测中... Inspection in progress..." + 平板采集进度提示 |
| 报告生成 | 完整质检报告（IMEI/电池/屏幕/外观评分）+ 抵扣报价 + "接受"/"拒绝"按钮 |

### 5.3 OTP 服务 (新增 CLOUD-P0-12)

**功能描述：** 店员输入手机号后，系统生成 6 位 OTP 并发送 SMS（含 H5 跟踪短链）。店员在平板输入 OTP，系统验证后完成身份确认。

**OTP 生命周期：**
```
[已生成] ──(3 分钟内输入正确)──→ [已验证]
     │
     ├──(3 次错误)──→ [已锁定 3min]
     │
     └──(3 分钟超时)──→ [已过期]
```

**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 生成时机 | 店员输入手机号并点击"发送验证码" |
| OTP 格式 | 6 位随机数字 |
| 有效期 | 3 分钟 |
| 最大尝试 | 3 次；超过锁定 60 秒 |
| 每日上限 | 同一手机号每天 5 次 |
| SMS 成本 | ₹0.15-0.30/条（MSG91 / Twilio / Exotel）|

### 5.4 H5 会话页面 (新增 CLOUD-P0-13)

**功能描述：** 用户点击 SMS 中的短链打开 H5 页面。页面根据当前会话状态自动展示对应内容：质检中、报告已生成、报价待确认、核销完成。不再需要用户做"授权/同意"操作（OTP 即授权）。

**页面状态与内容映射：**

| 会话状态 | H5 展示 |
|----------|---------|
| 会话已创建（质检中） | "正在检测您的设备..." + 进度提示 |
| 报告已生成 | 完整质检报告 + 抵扣报价 + 接受/拒绝按钮 |
| 用户已接受 | "报价已接受，等待核销确认" |
| 核销完成 | 核销成功摘要 |

## 六、OTP 替代了什么

| 原来的流程 | 替代方式 |
|-----------|----------|
| 线上预约 - 口头确认身份（"您是 Rajesh 先生？"） | OTP 验证 → 手机号归属即身份 |
| 直接到店 - 平板生成 H5 二维码 → 扫码 → 点击同意 | OTP 验证 + SMS 中点击链接即可，不再需要扫码 |
| 直接到店 - H5 授权页（隐私条款+质检授权） | OTP 即授权 + SMS 模板中注明质检范围 + 平板补充协议入口 |
| 直接到店 - 二维码 10 分钟过期需重新生成 | SMS 链接绑定 session，只要 session 存活就能访问 |

## 七、优势总结

| 维度 | 统一前 | 统一后 |
|------|--------|--------|
| 店员操作 | 两个入口，需判断用户类型 | **一个入口**：输入手机号 |
| 用户操作 | 预约零操作 / 到店扫码+点同意 | **统一**：看 SMS 报 OTP，后续点链接看报告 |
| 身份验证强度 | 口头 / H5 点击 | **OTP 手机号归属确权** |
| 等待时间 | 预约即时 / 到店 10-30 秒 | **统一 5-15 秒** |
| H5 交付方式 | 扫平板二维码（反光/光线差/摄像头差） | **SMS 链接直达**，不受环境光线影响 |
| 极端场景 | 没装 App 无法授权 | **有 SIM 卡就能走** |
| 预填信息 | 预约有，到店无 | **OTP 后自动匹配** |
