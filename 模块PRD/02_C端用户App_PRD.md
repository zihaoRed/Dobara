## P0 核心功能

## APP-P0-01 质检报告查看
**优先级：** P0
**功能描述：**
门店质检完成并上传数据后，云端推送质检报告至用户 App。用户可在 App 内查看完整的质检结果详情，包括设备硬件检测数据、外观影像、成色评级和抵扣报价。用户也可通过 SMS 中的 H5 短链接在未安装 App 的情况下查看报告。
**展示内容：**

| 区域 | 内容 |
|------|------|
| 报告头 | 设备品牌、型号、IMEI 后四位、质检时间 |
| 硬件检测摘要 | 电池健康度（进度条 + 百分比 + 状态标签）、屏幕状态、传感器、存储容量、摄像头、扬声器、按键（各项以正常/异常图标展示） |
| 外观影像 | 10 张外观照片可滑动查看 + 1 段 360° 旋转视频可全屏播放 |
| 外观评级 | 外观综合评级（A/B/C/D）及评级说明文字 |
| 抵扣报价 | 醒目展示最终抵扣金额（INR）+ 报价有效期倒计时 |

**外观评级说明（A/B/C/D 四档）：**

| 等级 | 等级名称 | 标签颜色 | 评级说明文字（面向用户） |
|------|---------|:---:|--------------------------|
| A | 99 新（几近全新） | 绿 | 外观无划痕、无磕碰，屏幕与边框完好如新；全原厂配件、无维修记录；电池健康度 ≥90%，所有功能正常 |
| B | 95 新（轻微使用痕迹） | 蓝 | 屏幕有轻微划痕（贴膜即可覆盖），边框轻微掉漆（少于 2 处）；全原厂、无维修记录；电池健康度 ≥85%，所有功能正常 |
| C | 90 新（明显使用痕迹） | 橙 | 屏幕可见明显划痕，边框有磕碰痕迹；可能存在非核心维修（如更换电池/后盖）；电池健康度 ≥80%，功能性问题不超过 1 项 |
| D | 85 新（大量瑕疵） | 红 | 外观瑕疵较多：屏幕碎裂或显示异常、边框变形或后盖碎裂，或有屏幕/主板更换记录；电池健康度 <80%，或存在 2 项及以上功能性问题 |

**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 推送时机 | 云端定价引擎完成计算后 5 秒内推送至用户 App |
| 报告访问入口 | App 内推送通知 + App 首页"我的报告"入口 + SMS H5 短链 |
| H5 兜底 | 未安装 App 的用户通过 SMS 中的短链查看报告，H5 页面随质检进度自动更新内容 |
| 电池健康度展示 | ≥85% 绿色 + "良好"；70%-85% 黄色 + "建议更换"；<70% 红色 + "需更换" |
| 照片查看 | 支持左右滑动、双指缩放、点击放大查看单张 |
| 视频播放 | 支持全屏播放、拖动进度条、暂停/播放控制 |
| 硬件检测项展示 | 正常项绿色对勾图标，异常项红色感叹号图标 |
| 报价有效期 | 生成后 30 分钟内有效，以倒计时格式 `MM:SS` 展示；超时后页面变灰并提示"报价已失效，请联系店员重新质检" |
| 报告缓存 | 报告数据在 App 本地缓存，用户可随时回看历史报告 |
**验收标准：**
- [ ] 质检完成后 5 秒内推送至用户 App
- [ ] 报告页展示所有硬件检测项及其状态（正常绿色 / 异常红色）
- [ ] 电池健康度以进度条 + 百分比 + 颜色标签展示
- [ ] 外观照片可左右滑动查看，支持双指缩放手势
- [ ] 外观评级每个等级均展示对应等级名称与说明文字，标签颜色正确（A 绿 / B 蓝 / C 橙 / D 红）
- [ ] 质检视频支持全屏播放、拖动进度条
- [ ] 抵扣金额以醒目字号和颜色展示
- [ ] 报价有效期以倒计时形式呈现，超时后按钮置灰
- [ ] 报告页底部固定展示"接受报价"和"拒绝报价"两个操作按钮
- [ ] H5 短链在未安装 App 时正常打开并展示报告内容

## APP-P0-02 接受 / 拒绝报价
**优先级：** P0
**功能描述：**
用户在查看完整质检报告后，可选择接受或拒绝抵扣报价。接受后系统触发核销流程；拒绝后本次换购会话关闭。操作结果实时同步至云端并推送门店平板。
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 操作入口 | 质检报告页底部固定两个按钮：绿色"接受报价"、灰色"拒绝报价"，不随页面滚动隐藏 |
| 接受-二次确认 | 点击"接受"后弹出确认弹窗，标题"确认接受报价？"，正文"确认接受 ₹XX 抵扣报价？接受后将无法撤回"，按钮："确认接受" / "我再想想" |
| 拒绝-二次确认 | 点击"拒绝"后弹出确认弹窗，标题"确认拒绝报价？"，正文"拒绝报价后本次换购将取消，如需重新质检请联系门店店员"，按钮："确认拒绝" / "我再想想" |
| 超时处理 | 报价有效期 30 分钟倒计时归零后，两个按钮自动变灰不可点击，页面顶部展示红色横幅"报价已失效，请联系店员重新质检" |
| 不可撤回 | 接受或拒绝操作确认后不可撤回 |
| 状态同步 | 操作结果在 3 秒内同步至云端，云端推送至门店平板，平板同步更新核销状态 |
| 接受后流程 | 接受报价 → 系统生成核销码推送至店老板 App → 进入核销环节（由 TAB-P0-05 承接） |
| 拒绝后流程 | 拒绝报价 → 换购会话标记为 [已拒绝] → 返回 App 首页 |
**验收标准：**
- [ ] "接受报价"和"拒绝报价"按钮在报告页底部固定展示，不随页面滚动隐藏
- [ ] 点击"接受"弹出二次确认弹窗，确认后不可撤回
- [ ] 点击"拒绝"弹出二次确认弹窗，确认后返回首页
- [ ] 报价超时后按钮置灰不可操作，页面展示失效提示
- [ ] 接受后 3 秒内平板收到核销状态更新
- [ ] 拒绝后会话状态标记为 [已拒绝]

## APP-P0-03 商城浏览
**优先级：** P0
**功能描述：**
用户可在 App 内浏览所有在库可售的二手设备。商品以列表或网格视图展示（用户可切换），支持按品牌、机型、成色等级、价格区间、存储容量、颜色进行筛选和排序。每个商品卡片展示设备缩略图、品牌型号、成色等级标签、售价和所在城市。
**功能要点：**

| 功能 | 说明 |
|------|------|
| 展示视图 | 列表视图（默认）+ 网格视图（2 列），用户可一键切换 |
| 筛选 | 品牌、机型、成色等级（A/B/C/D）、价格区间（双滑块，INR）、存储容量、颜色 |
| 排序 | 价格从低到高 / 从高到低、入库时间最早优先（FIFO）、上架时间最新、成色等级优先 |
| 商品卡片 | 设备主图缩略图 + 品牌型号 + 成色等级标签（彩色）+ 售价（INR）+ 所在城市 |
| 商品详情 | 点击卡片进入详情页，分为"机况信息"和"参数规格"两个 Tab |
| 搜索 | 顶部搜索框，支持品牌名 / 型号关键词搜索（详见 APP-P0-10） |
| IMEI 展示规则 | 列表页不展示 IMEI；详情页仅展示 IMEI 后四位 |
**验收标准（列表与筛选）：**
- [ ] 列表页支持按品牌、机型、成色等级、价格区间、存储容量、颜色组合筛选
- [ ] 筛选条件可组合使用，选中条件以标签形式展示在顶部，支持单独移除
- [ ] 筛选结果实时更新，无结果时展示空状态提示并引导"调整筛选条件"或"查看全部设备"
- [ ] 支持列表视图与网格视图（2 列）一键切换，切换时保持当前筛选条件
- [ ] 商品卡片展示主图缩略图、品牌型号、成色等级标签（彩色）、售价、所在城市
- [ ] IMEI 在列表页不展示
- [ ] 排序选项切换后列表即时重新排列

## 商品详情展示内容
商品详情页分为两个 Tab："机况信息"和"参数规格"。机况信息为该台设备独有的检测结果，因设备而异；参数规格为该型号设备的固定参数，同型号所有设备共享同一套规格数据。

**Tab 1：机况信息（Condition Info）**
展示该台设备经过质检和审核后的实际状态，所有字段来自质检数据和审核结果。

| 展示项 | 数据来源 | 展示形式 | 说明 |
|--------|----------|----------|------|
| 成色等级 | 定价引擎 + 审核 | 等级标签（A/B/C/D）+ 等级名称 | 如 "A - 99 新（几近全新）"；四档等级名称与说明文字见 APP-P0-01 外观评级说明 |
| 商品主图 | 审核时上传 | 首屏大图轮播（1-3 张精修主图） | 审核时上传的设备精修图，用于列表和详情主图；可左右滑动 |
| 外观实拍 | 平板质检 | 网格缩略图（10 张），点击可放大查看 | 平板拍摄的 10 个角度外观照片；支持单张全屏查看 + 左右滑动 |
| 质检视频 | 平板质检 | 视频播放器 | 360° 旋转视频；支持全屏播放、进度拖动 |
| 电池健康度 | 硬件检测 | 进度条 + 百分比 + 状态标签 | ≥85% 绿色 "良好"；70%-85% 黄色 "建议更换"；<70% 红色 "需更换" |
| 屏幕外观 | 外观点检 | 文字描述 | 如 "轻微划痕，贴膜后可覆盖" |
| 屏幕显示 | 外观点检 | 文字描述 | 如 "显示正常，无色差无坏点" |
| 机身外观 | 外观点检 | 文字描述 | 如 "边框轻微掉漆（< 2 处）" |
| 维修历史 | 硬件检测 + 店员勾选 | 标签列表 | 如 "更换过电池"、"屏幕非原厂"；无维修时展示"无维修记录" |
| 功能性问题 | 硬件检测 + 店员勾选 | 标签列表 | 如 "Face ID 不可用"；无问题时展示 "✓ 全部功能正常" |
| 配件完整性 | 店员勾选 | 标签列表 | 如 "含原装充电器、数据线" / "无包装盒" |
| 是否在保 | 店员勾选 | 标签 | "在保"（绿色）/ "已过保"（灰色） |
| 存储容量 | 硬件检测 | 文字 | 如 "256GB" |
| 颜色 | 店员勾选 | 色块 + 颜色名 | 如 "● 石墨色" |
| 售价 | 定价引擎 | 醒目金额展示 | INR 数字 + "含税"标签 |
| 发票/保修凭证 | 质检环节采集 | 照片缩略图 | 若有发票，展示发票照片缩略图，点击可查看大图；作为二次购买用户的官方保修依据 |
**验收标准（机况信息 Tab）：**
- [ ] 商品主图支持大图轮播，可左右滑动，显示当前图片序号（如 "1/3"）
- [ ] 外观实拍 10 张照片以网格缩略图展示，点击可全屏查看，支持左右滑动
- [ ] 质检视频支持全屏播放、拖动进度条、暂停/播放
- [ ] 电池健康度以进度条 + 百分比 + 颜色状态标签展示（≥85% 绿、70%-85% 黄、<70% 红）
- [ ] 屏幕外观、屏幕显示、机身外观以可读文字描述展示
- [ ] 维修历史、功能性问题和配件完整性以标签列表展示
- [ ] 成色等级以彩色标签（A 绿/B 蓝/C 橙/D 红）+ 等级名称展示
- [ ] 售价以醒目字体展示 INR 金额 + "含税"标签
- [ ] 若有发票信息，展示发票照片缩略图入口

**Tab 2：参数规格（Specifications）**
展示该型号设备的出厂固定参数，由管理员在后台"设备品类管理"中维护，同型号所有设备共享同一套规格数据。

| 分类 | 展示项 | 说明 |
|------|--------|------|
| 基本信息 | 品牌、型号、发布年份 | 如 Apple iPhone 12 (2020) |
| 处理器 | 芯片型号、核心数 | 如 Apple A14 Bionic (6 核) |
| 内存与存储 | RAM 容量 | 如 4GB RAM（该字段同型号固定；实际存储容量见机况信息 Tab） |
| 显示屏 | 尺寸、分辨率、刷新率、面板类型 | 如 6.1" OLED, 2532 x 1170, 60Hz |
| 后置摄像头 | 像素、光圈、镜头数量 | 如 12MP 广角 + 12MP 超广角, f/1.6 |
| 前置摄像头 | 像素、光圈 | 如 12MP, f/2.2 |
| 电池 | 额定容量 (mAh)、充电功率 | 如 2815mAh, 20W 有线快充 |

## APP-P0-05 用户注册与登录
**优先级：** P0
**功能描述：**
用户通过手机号 + OTP 验证码完成注册或登录，首次注册需设置登录密码并确认用户协议。支持密码登录和验证码登录两种方式。已注册用户可通过手机号 + 密码直接登录，或通过手机号 + OTP 快捷登录。
**注册流程：**

```
启动 App → 进入登录/注册页
  → 输入手机号（自动识别国家代码，默认 +91）
  → 点击"获取验证码"
  → 系统发送 6 位 SMS OTP
  → 用户输入 OTP（3 分钟内有效）
  → 系统校验手机号：
      ├── 新用户（首次注册）→ 进入"设置密码"页面
      │     → 设置登录密码（满足密码规则）
      │     → 确认密码
      │     → 展示用户协议 + 隐私政策
      │     → 用户勾选"我已阅读并同意"（必勾选）
      │     → 点击"完成注册"
      │     → 账号创建成功 → 进入 App 首页
      └── 已有账号 → 直接登录 → 进入 App 首页

```
**登录流程：**

```
App 登录页
  ├── 密码登录：
  │     → 输入手机号
  │     → 输入密码
  │     → 点击"登录"
  │     → 校验通过 → 进入 App 首页
  │     → 校验失败 → 提示"手机号或密码错误"（不区分手机号/密码具体错误）
  │
  └── 验证码登录：
        → 输入手机号
        → 点击"获取验证码"
        → 输入 OTP
        → 校验通过 → 进入 App 首页

```
**密码规则：**

| 规则项 | 说明 |
|--------|------|
| 最小长度 | 8 位 |
| 最大长度 | 20 位 |
| 复杂度要求 | 必须包含以下四类字符中的至少两类：大写字母、小写字母、数字、特殊字符（!@#$%^&*()_+-=[]{};':"\|,.<>/?） |
| 不允许内容 | 不允许包含 3 位及以上连续重复字符（如 "aaa"、"111"）；不允许包含 3 位及以上连续递增/递减数字（如 "123"、"987"） |
| 密码强度指示 | 输入密码时实时显示密码强度：弱（仅一类字符）/ 中（两类字符）/ 强（三类及以上字符），以颜色条展示 |
| 确认密码 | 设置密码时必须再次输入以确认一致，两次输入不一致时提示"两次密码输入不一致" |
| 修改密码 | 个人中心 → 账户安全 → 修改密码；需先输入原密码验证，再输入新密码；修改成功后所有已登录设备强制退出，需重新登录 |
**OTP 设计：**

| 设计点 | 说明 |
|--------|------|
| OTP 长度 | 6 位数字 |
| 有效期 | 3 分钟，过期需重新发送；倒计时展示"XX 秒后重新获取" |
| 发送渠道 | MSG91 SMS（优先），WhatsApp Business API（备选） |
| 重试次数 | 同一手机号每天最多发送 5 次 OTP；超过后提示"今日验证码发送次数已达上限，请明日再试" |
| 冷却时间 | 发送后 60 秒内不可重复发送，按钮展示倒计时 |
| 验证次数 | OTP 输入错误最多 3 次；超过后当前 OTP 失效，需重新发送 |
| 防刷机制 | 同一设备 / IP 每小时最多请求 10 次 OTP；超过后临时限制 1 小时 |
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 手机号格式 | 印度手机号，10 位数字，以 6/7/8/9 开头；自动补全 +91 国家代码 |
| 手机号唯一 | 一个手机号对应一个用户账号，不可重复注册 |
| 登录态持久 | 登录成功后 token 有效期 30 天，30 天内免登录；用户主动退出或修改密码后 token 失效 |
| 首次注册来源标记 | 通过线下门店 OTP 验证自动创建的账号，标记来源为"线下注册"；通过 App 自主注册的账号，标记来源为"App 注册" |
| 用户协议确认 | 首次注册时必须勾选同意《用户协议》和《隐私政策》（需分别提供可点击查看的链接），未勾选时"完成注册"按钮置灰不可点击 |
| 协议查看 | 登录页底部提供《用户协议》和《隐私政策》的查看入口，用户可在登录前阅读 |
| 多设备登录 | 同一账号可在多台设备同时登录（MVP 阶段不做踢出限制），修改密码后所有设备 token 失效 |
| 注销账号 | 账号一旦注销不可恢复；注销时需二次确认 + OTP 验证；注销后 30 天冷静期内可联系客服恢复 |
**验收标准：**
- [ ] 手机号输入框自动识别 +91 国家代码，格式化展示（如 +91 98765 43210）
- [ ] OTP 发送后按钮展示 60 秒倒计时，期间不可再次点击
- [ ] OTP 输入错误时提示剩余尝试次数，3 次错误后 OTP 失效
- [ ] 新用户注册时引导设置密码，密码强度实时指示
- [ ] 密码不符合规则时给出具体提示（如"密码长度不足 8 位"、"需至少包含两类字符"）
- [ ] 确认密码不一致时给出提示
- [ ] 用户协议和隐私政策可点击查看全文
- [ ] 未勾选协议时"完成注册"按钮置灰
- [ ] 已注册用户 OTP 验证通过后直接登录，不重复设置密码
- [ ] 密码登录和验证码登录两种方式可自由切换

- [ ] 修改密码后所有设备强制退出，需重新登录

```

  → 展示注销须知（列出注销后果）：

```
**业务规则：**

| OTP 验证 | 注销需通过手机号 OTP 验证身份 |
| 不可逆 | 冷静期过后数据物理删除，不可恢复 |
**验收标准：**

**功能描述：**
用户从商品详情页点击"立即购买"后进入订单确认页，在此确认/选择收货地址、查看商品详情和金额明细、选择配送方式和支付方式，最后点击"提交订单"完成库存锁定并进入支付环节。支付支持 Razorpay UPI，支付失败时支持重试。
> **锁单时序修正（关键）：** 原方案中"立即购买"即锁单的设计存在缺陷——用户在未确认收货地址、支付方式等必要信息前即占用库存。修正后流程为：立即购买 → 进入订单确认页（不锁单）→ 用户确认所有信息 → 点击"提交订单" → 系统锁单（5 分钟）→ 进入支付。此修正确保锁单发生在用户已完成所有信息确认、具备支付意愿的时刻。
**完整流程图：**

```
商品详情页
  → 点击"立即购买"
  → 库存状态校验（仅校验，不锁单）
      ├── 已锁定/已售出 → 提示不可购买
      └── 可售 → 进入订单确认页
            │
            ├── 确认/选择收货地址
            ├── 查看商品信息（设备图、型号、成色、IMEI后四位、单价）
            ├── 查看金额明细（商品金额 + 配送费 + 税费 = 实付金额）
            ├── 选择配送方式（标准配送/快速配送）
            └── 选择支付方式（UPI / 已绑定UPI / 银行卡）
            │
            → 点击"提交订单"
            → [新增] 校验配送区域（Pincode Serviceability）
                  ├── ✅ 可配送 → 继续
                  └── ❌ 不可配送 → 提示"该地区暂不支持配送，请更换收货地址"
                                    → 阻止提交，不锁定库存，不生成订单
            → 系统锁定 IMEI 库存（5 分钟锁定）
            → 生成订单（状态：待支付）
            → 唤起 Razorpay UPI 支付
                  │
                  ├── 支付成功 → 跳转支付成功页（展示订单号）
                  │              → 订单状态变更为"待发货"
                  │
                  ├── 支付失败 → 展示支付失败页
                  │              → 展示失败原因
                  │              → 提供"重新支付"按钮
                  │              → 锁定持续（5 分钟内可重试）
                  │
                  └── 超时未支付 → 5 分钟倒计时归零
                                   → 自动取消订单
                                   → 释放 IMEI 锁定
                                   → 推送通知"订单已超时取消"
                                   → 设备恢复可售

```
**订单确认页展示内容：**

| 信息区域 | 展示内容 |
|----------|----------|
| 收货地址区 | 收货人姓名、手机号、完整地址（可点击切换其他地址）；若无地址，提示"请添加收货地址"并提供入口 |
| 配送区域状态 | 地址下方展示 pincode 配送校验结果：✅ 支持配送（绿色）· 预计 3-5 个工作日送达 / ❌ 该地区暂不支持配送（红色）· 请更换收货地址；选择/修改地址后 1 秒内实时更新校验结果；不可配送时"提交订单"按钮置灰 |
| 商品信息区 | 设备主图缩略图、品牌型号、成色等级标签、IMEI 后四位、存储容量、颜色 |
| 金额明细区 | 商品金额（INR）、配送费（INR）、税费（INR）、合计实付金额（INR，醒目展示） |
| 配送方式区 | 标准配送（默认，3-5 个工作日）/ 快速配送（1-2 个工作日，加价），用户单选 |
| 支付方式区 | UPI（Razorpay UPI Intent）/ 已绑定 UPI ID / 银行卡（若有），用户单选；默认选中上次使用的支付方式 |
| 锁定倒计时 | 提交订单后显示 5 分钟倒计时（MM:SS 格式），提示"请在 XX:XX 内完成支付，超时订单将自动取消" |
| 底部按钮 | 提交前："提交订单"（主按钮，橙色醒目）；提交后进入支付等待时不可见 |
**支付失败处理：**

| 失败场景 | 处理方式 |
|----------|----------|
| UPI App 支付失败 | 展示失败原因（银行返回的错误描述），提供"重新支付"按钮，锁单时间继续倒计时 |
| 用户在 UPI App 中取消支付 | 展示"支付已取消"，提供"重新支付"和"更换支付方式"两个按钮 |
| 网络超时/中断 | 展示"支付状态未知，正在查询..."，自动查询支付结果；若未支付成功，提供重新支付入口 |
| 余额不足 | 展示"账户余额不足"，建议更换支付方式或充值后重试 |
| 5 分钟锁单超时 | 倒计时归零后自动取消订单，释放库存，推送通知，设备恢复可售 |

| 展示内容 | 说明 |

| 成功图标 | 绿色对勾动画 |
| 订单号 | 唯一订单编号，支持复制 |
| 订单摘要 | 设备信息 + 实付金额 |

| 操作按钮 | "查看订单详情"（跳转订单详情页）、"继续购物"（跳转商城首页） |
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 锁单时机 | 点击"提交订单"时锁定 IMEI 库存，非"立即购买"时 |
| 锁定时长 | 5 分钟，倒计时在支付等待页实时展示 |
| 锁单释放触发条件 | (1) 支付成功 → 订单转为待发货，锁定解除（库存状态变为"已售出"）；(2) 5 分钟超时 → 订单自动取消，锁定释放（库存状态变为"可售"）；(3) 用户主动取消订单 → 锁定释放 |
| 支付方式 | MVP 阶段集成 Razorpay UPI Intent，支持 PhonePe / Google Pay / Paytm 等主流 UPI App |
| 支付确认 | 以 Razorpay 回调确认为准，前端收到 success callback 后展示成功页；若回调延迟，展示"支付处理中"loading 状态，防止重复支付 |
| 重复支付防护 | 同一订单号在 Razorpay 侧做幂等控制；前端在支付进行中时禁用所有操作按钮 |
| 地址必填 | 至少存在一个收货地址方可提交订单；无地址时"提交订单"按钮置灰并提示 |
| 配送区域校验 | 提交订单前必须校验收货地址 pincode 是否在发货仓库的物流覆盖范围内；校验在用户选择/修改收货地址时自动触发（防抖 500ms）；不可配送时阻止提交并引导用户更换地址 |
| 校验数据源 | 主数据源：服务端本地 pincode 覆盖表（每日凌晨同步自 Delhivery）；辅助数据源：Delhivery Pincode Serviceability API 实时查询；API 不可用时降级为本地 DB 查询，记录告警 |
| B2B 拆单场景 | 多仓库发货时，每个子订单的收货地址需分别校验 pincode（若主订单含 N 个仓库，任一仓库不可配送则该子订单对应的设备不可购买） |
| 配送费用规则 | 标准配送统一 INR 50；快速配送 INR 150；订单金额超过 INR 5,000 时标准配送免运费 |
| 税费规则 | GST 按商品售价的 18% 计算（印度 GST）；税费在金额明细中单独列示 |

## APP-P0-08 订单取消
**优先级：** P0
**功能描述：**
用户可在订单不同状态下发起取消操作。待支付订单取消时释放库存锁定；待发货订单取消时按规则退款；已发货订单取消需先拒收或退回后再处理。不同订单状态对应不同的取消规则和退款策略。
**取消规则（按订单状态）：**

| 订单状态 | 可取消 | 库存处理 | 退款规则 |
|----------|--------|----------|----------|
| 待支付 | 是 | 立即释放 IMEI 锁定，设备恢复可售 | 无需退款（未支付） |
| 待发货 | 是 | 设备重新上架为可售 | 全额退款（商品金额 + 配送费 + 税费），原路退回 |
| 配送中 | 否（需先拒收） | 设备标记为退回中，退回原仓库重新质检后上架 | 拒收后退款：退回商品金额 + 税费，扣除往返运费 |
| 已签收 | 否（走售后流程） | — | 不适用（需走售后申请，见 APP-P0-09） |
| 已完成（超过 7 天） | 否 | — | 不适用 |
**取消流程：**

```
订单详情页 → 点击"取消订单"
  ├── 待支付订单：
  │     → 弹窗确认："确定取消订单？取消后该设备将被释放"
  │     → 确认 → 取消订单 → 释放库存 → 状态变为"已取消"
  │
  ├── 待发货订单：
  │     → 弹窗确认："确定取消订单？将全额退款至您的原支付方式"
  │     → 确认 → 取消订单 → 设备重新上架
  │     → 系统发起退款（原路退回）
  │     → 展示退款进度："预计 5-7 个工作日到账"
  │     → 状态变为"已取消（退款中）"
  │
  └── 配送中订单：
        → 提示"订单已在配送中，不可直接取消"
        → 提供操作指引："您可在收到商品时拒收，或签收后走售后流程"
        → 展示"拒收操作说明"和"联系客服"入口

```

**配送中拒收退回流程（退回入库）：**

```
用户当面拒收 / 物流派送失败退回
  → 订单状态 → [退回中]
  → 设备退回原仓库，交库管重新质检（检查防拆标签是否完整、有无人为拆机/损坏）
  → 标签完好且与出库记录一致 → 设备重新上架为可售
  → 标签损坏 / 设备异常 → 进入争议处理（部分退款/拒退）
  → 系统发起退款：退回商品金额 + 税费，扣除往返运费
```

**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 取消入口 | 订单详情页底部"取消订单"按钮（仅可取消的订单状态展示） |
| 二次确认 | 所有取消操作均需弹窗二次确认，展示取消后果说明 |
| 库存释放 | 待支付订单取消后立即释放库存，秒级生效 |
| 退款时效 | 待发货订单取消后，退款在 5-7 个工作日内原路退回（Razorpay 处理时效） |
| 退款方式 | 原路退回至用户支付的 UPI 账户 / 银行卡；不支持退款至其他账户 |
| 退款通知 | 退款发起和到账时分别推送 App 通知 |
| 取消原因 | MVP 阶段不强制要求选择取消原因；P2 阶段加入取消原因收集用于分析 |
| 配送中订单 | 不可直接取消；引导用户拒收或走售后；提供联系客服入口 |
| 已签收订单 | 不可取消；引导走售后申请流程（见 APP-P0-09） |
**验收标准：**
- [ ] 待支付订单取消后库存立即释放，设备在商城中恢复可售
- [ ] 待发货订单取消后设备重新上架，系统发起全额退款
- [ ] 退款金额 = 商品金额 + 配送费 + 税费（全额退）
- [ ] 退款进度在订单详情中展示："已发起退款 → 银行处理中 → 已到账"
- [ ] 配送中订单点击"取消订单"时提示不可取消并给出操作指引
- [ ] 已签收/已完成订单不展示"取消订单"按钮
- [ ] 所有取消操作均有二次确认弹窗
- [ ] 退款到账后推送通知"您的订单退款已到账"

## APP-P0-09 售后申请
**优先级：** P0
**功能描述：**
用户签收设备后发现商品存在与描述不符的质量问题，或商品在运输过程中出现损坏，可通过 App 提交售后申请。售后类型包括退货退款、换货和维修（P2）。用户需选择售后原因、上传举证照片，并选择退货物流方式。售后流程覆盖申请提交、审核、上门取件/自行寄回、退款/换货、售后状态追踪的完整闭环。
**售后类型：**

| 售后类型 | 适用条件 | 说明 |
|----------|----------|------|
| 退货退款 | 商品与描述严重不符、商品存在未披露的功能性缺陷、运输损坏 | 退回商品 → 全额退款（含配送费） |
| 换货 | 商品存在可修复的质量问题、发错型号/颜色/存储容量 | 退回商品 → 发换同型号同级设备 |
| 维修（P2） | 商品签收后 7 天内出现非人为功能性故障 | 寄修或上门维修 |
**售后申请流程：**

```
订单详情页 → 点击"申请售后"
  → 选择售后类型：退货退款 / 换货
  → 选择售后原因（从预设列表中选择）
  → 上传举证材料（照片/视频）
  → 填写问题描述（可选，最多 500 字）
  → 选择退货物流方式：上门取件 / 自行寄回
  → 确认退款方式（原路退回 / 退回至钱包余额）
  → 提交售后申请
  → 系统生成售后单号
  → 进入审核流程

```
**退货原因分类（预设，用户单选）：**

| 原因类别 | 具体原因选项 |
|----------|-------------|
| 外观与描述不符 | 成色等级与描述不符、有明显未披露的划痕/磕碰、屏幕有未披露的划痕/坏点、机身有未披露的变形/凹陷 |
| 功能性问题 | 电池续航严重不足（低于检测值 20% 以上）、屏幕触摸失灵/断触、摄像头无法使用/成像异常、扬声器/麦克风异常、按键失灵、Face ID/Touch ID 不可用（描述中未说明）、无法开机/频繁重启、存储容量与描述不符 |
| 发错商品 | 型号错误、颜色错误、存储容量错误 |
| 运输损坏 | 包装完好但设备损坏、包装破损导致设备损坏 |
| 配件缺失 | 描述中包含的配件未收到 |
| 其他问题 | 需补充描述（必填，最少 20 字） |
**举证上传规则：**

| 规则项 | 说明 |
|--------|------|
| 必传照片 | 最少 2 张照片：1 张设备全景照（含屏幕）+ 1 张问题部位特写 |
| 最多上传 | 9 张照片 + 1 段视频（最长 30 秒，用于展示功能性问题） |
| 格式支持 | 照片：JPG / PNG / HEIC；视频：MP4 / MOV |
| 单文件大小 | 照片 ≤ 10MB；视频 ≤ 50MB |
| 拍照/选相册 | 支持现场拍照和从相册选择两种方式 |
| 示例引导 | 每种售后原因展示对应的拍照示例图（如"请拍摄屏幕划痕特写，参照下图"） |
**退货物流方式：**

| 物流方式 | 说明 | 费用承担 |
|----------|------|----------|
| 上门取件 | 平台安排物流人员上门取件；用户选择取件时间段（上午 9-12 / 下午 12-5） | 商品质量问题：平台承担；用户个人原因：用户承担（从退款中扣除 INR 100） |
| 自行寄回 | 用户自行联系物流寄回；上传物流单号和物流公司名称 | 商品质量问题：用户先行垫付运费，退款时一并退回（需上传运费凭证）；用户个人原因：用户承担 |
**退款规则：**

| 退款场景 | 退款范围 | 退款时效（从审核通过起算） |
|----------|----------|--------------------------|
| 商品质量问题退货 | 商品金额 + 配送费 + 税费（全额） | 5-7 个工作日 |
| 发错商品退货 | 商品金额 + 配送费 + 税费（全额） | 5-7 个工作日 |
| 运输损坏退货 | 商品金额 + 配送费 + 税费（全额） | 5-7 个工作日 |
| 用户个人原因退货 | 商品金额 + 税费（扣除往返运费 INR 100 × 2） | 5-7 个工作日 |
| 换货 | 不涉及退款，重新发货 | 审核通过后 1-2 个工作日发出 |
**换货流程：**

```
售后申请（选择"换货"）
  → 审核通过 → 用户退回商品（上门取件/自行寄回）
  → 仓库签收退回商品并验收
  → 系统匹配同型号同成色等级替换设备
  → 若无匹配设备：
      ├── 用户同意等待补货（最长 7 天）
      └── 用户不同意 → 转为退货退款
  → 替换设备发货 → 更新物流信息 → 用户签收 → 售后完成

```

| 锁单前置条件 | 无（用户看到价格即锁单） | 用户已确认收货地址、配送方式、支付方式 | APP-P0-07 |
**本次修正的完整逻辑已整合至 APP-P0-07 确认订单与支付 中，此处为修正追溯说明，不单独产生开发任务。**

## APP-P2-02 评价系统

## APP-P2-04 收藏/心愿单
**优先级：** P2
**功能描述：**
用户可将心仪的二手设备加入收藏/心愿单，方便后续快速查找和购买。已收藏设备发生降价或库存状态从"已售出/已锁定"变为"可售"（补货/释放）时，系统推送通知提醒用户。
**收藏操作：**

| 操作 | 入口 | 行为 |
|------|------|------|
| 添加收藏 | 商品详情页"收藏"图标（心形）+ 商品列表卡片"收藏"图标 | 点击收藏图标，图标变为实心红心，设备加入心愿单 |
| 取消收藏 | 商品详情页"已收藏"图标 + 心愿单列表左滑删除 | 点击取消收藏，图标变为空心，设备从心愿单移除 |
| 查看心愿单 | App 底部导航栏或个人中心入口 | 进入心愿单页面 |
**心愿单列表：**

| 展示项 | 说明 |
|--------|------|
| 商品卡片 | 与商城列表一致的设备卡片 + 收藏时间 |
| 库存状态 | 实时展示当前库存状态：可售（绿色）/ 已锁定（橙色）/ 已售出（灰色） |
| 价格变动 | 若已收藏设备降价，价格旁展示"已降 INR XXX"标签 |
| 快捷购买 | 可售状态的设备提供"立即购买"按钮直接跳转订单确认页 |
| 排序 | 按收藏时间降序（最近收藏在前）/ 按价格 / 按库存状态（可售优先） |
**通知提醒规则：**

| 触发条件 | 通知内容 |
|----------|----------|
| 已收藏设备降价 | "您收藏的 [型号] 降了 INR XXX，快去看看吧！" |
| 已收藏设备从已售出变为可售（补货/库存释放） | "您收藏的 [型号] 已重新上架，库存有限！" |

**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 收藏数量上限 | 最多收藏 200 台设备；超出时提示"心愿单已满（200），请清理后再添加" |
| 收藏持久化 | 收藏数据与账号绑定，换设备登录后自动同步 |
| 降价通知 | 仅当设备降价 ≥ 5% 或 ≥ INR 500（取较小值）时触发通知，避免小额波动频繁打扰 |
| 已售出处理 | 已收藏设备售出后在心愿单中保留（灰色置灰），展示"已售出"标签；用户可手动移除 |
| 补货通知 | 已售出的收藏设备若 7 天内重新上架（退货/取消），推送补货通知 |
**验收标准：**
- [ ] 商品详情页和列表页支持收藏/取消收藏，心形图标状态实时切换
- [ ] 心愿单展示所有已收藏设备，含库存状态和价格变动提示

- [ ] 已收藏设备从已售出变为可售时推送补货通知
- [ ] 心愿单最多收藏 200 台，超出时提示
- [ ] 已售出的收藏设备在心愿单中置灰保留，可手动移除
- [ ] 心愿单数据与账号绑定，跨设备同步
- [ ] 心愿单列表支持排序（收藏时间/价格/库存状态）
