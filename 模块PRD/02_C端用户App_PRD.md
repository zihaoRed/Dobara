## 文档说明
本文档是 C 端用户 App 模块的完整产品需求文档，涵盖 P0（核心）、P1（重要）、P2（体验增强）三级功能。每条功能编号格式为 `APP-Px-xx`，包含功能描述、业务规则和验收标准，作为 iOS / Android 开发、测试和产品验收的统一参考。
本文档对原功能描述文档及需求补充内容进行了整合、增补和修正，其中：
- **APP-P0-05 至 APP-P0-10** 为基于需求补充文档新增的 P0 级核心功能
- **APP-P0-07** 中的锁单时序已按需求补充 APP-10 / APP-11 进行修正（锁单节点从"立即购买"改为"提交订单"）
- **APP-P1-06 至 APP-P1-09** 以及 **APP-P2-02 至 APP-P2-04** 为新增的 P1/P2 功能

## APP-P0-01 质检报告查看
**优先级：** P0
**功能描述：**
门店质检完成并上传数据后，云端推送质检报告至用户 App。用户可在 App 内查看完整的质检结果详情，包括设备硬件检测数据、外观影像、成色评级和抵扣报价。用户也可通过 SMS 中的 H5 短链接在未安装 App 的情况下查看报告。
**展示内容：**

| 区域 | 内容 |
|------|------|
| 报告头 | 设备品牌、型号、IMEI 后四位、质检时间 |
| 硬件检测摘要 | 电池健康度（进度条 + 百分比 + 状态标签）、屏幕状态、传感器、存储容量、摄像头、扬声器、按键（各项以正常/异常图标展示） |
| 外观影像 | 10 张外观照片可滑动查看 + 1 段 360° 旋转视频可全屏播放 |
| 外观评级 | 外观综合评级（A/B/C/D）及评级说明文字 |
| 抵扣报价 | 醒目展示最终抵扣金额（INR）+ 报价有效期倒计时 |

**外观评级说明（A/B/C/D 四档）：**

| 等级 | 等级名称 | 标签颜色 | 评级说明文字（面向用户） |
|------|---------|:---:|--------------------------|
| A | 99 新（几近全新） | 绿 | 外观无划痕、无磕碰，屏幕与边框完好如新；全原厂配件、无维修记录；电池健康度 ≥90%，所有功能正常 |
| B | 95 新（轻微使用痕迹） | 蓝 | 屏幕有轻微划痕（贴膜即可覆盖），边框轻微掉漆（少于 2 处）或边框轻微划痕（反光角可见）；全原厂、无维修记录；电池健康度 ≥85%，所有功能正常 |
| C | 90 新（明显使用痕迹） | 橙 | 屏幕可见明显划痕，边框有磕碰痕迹；可能存在非核心维修（如更换电池/后盖）；电池健康度 ≥80%，功能性问题不超过 1 项 |
| D | 85 新（大量瑕疵） | 红 | 外观瑕疵较多：屏幕碎裂或显示异常、边框变形或后盖碎裂，或有屏幕/主板更换记录；电池健康度 <80%，或存在 2 项及以上功能性问题 |

**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 推送时机 | 云端定价引擎完成计算后 5 秒内推送至用户 App |
| 报告访问入口 | App 内推送通知 + App 首页"我的报告"入口 + SMS H5 短链 |
| H5 兜底 | 未安装 App 的用户通过 SMS 中的短链查看报告，H5 页面随质检进度自动更新内容 |
| 电池健康度展示 | ≥85% 绿色 + "良好"；70%-85% 黄色 + "建议更换"；<70% 红色 + "需更换" |
| 照片查看 | 支持左右滑动、双指缩放、点击放大查看单张 |
| 视频播放 | 支持全屏播放、拖动进度条、暂停/播放控制 |
| 硬件检测项展示 | 正常项绿色对勾图标，异常项红色感叹号图标 |
| 报价有效期 | 生成后 30 分钟内有效，以倒计时格式 `MM:SS` 展示；超时后页面变灰并提示"报价已失效，请联系店员重新质检" |
| 报告缓存 | 报告数据在 App 本地缓存，用户可随时回看历史报告 |
**验收标准：**
- [ ] 质检完成后 5 秒内推送至用户 App
- [ ] 报告页展示所有硬件检测项及其状态（正常绿色 / 异常红色）

- [ ] 外观照片可左右滑动查看，支持双指缩放手势
- [ ] 外观评级每个等级均展示对应等级名称与说明文字，标签颜色正确（A 绿 / B 蓝 / C 橙 / D 红）
- [ ] 质检视频支持全屏播放、拖动进度条
- [ ] 抵扣金额以醒目字号和颜色展示

## APP-P0-02 接受 / 拒绝报价
**优先级：** P0
**功能描述：**
用户在查看完整质检报告后，可选择接受或拒绝抵扣报价。接受后系统触发核销流程；拒绝后本次换购会话关闭。操作结果实时同步至云端并推送门店平板。
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 操作入口 | 质检报告页底部固定两个按钮：绿色"接受报价"、灰色"拒绝报价"，不随页面滚动隐藏 |
| 接受-二次确认 | 点击"接受"后弹出确认弹窗，标题"确认接受报价？"，正文"确认接受 ₹XX 抵扣报价？接受后将无法撤回"，按钮："确认接受" / "我再想想" |
| 拒绝-二次确认 | 点击"拒绝"后弹出确认弹窗，标题"确认拒绝报价？"，正文"拒绝报价后本次换购将取消，如需重新质检请联系门店店员"，按钮："确认拒绝" / "我再想想" |
| 超时处理 | 报价有效期 30 分钟倒计时归零后，两个按钮自动变灰不可点击，页面顶部展示红色横幅"报价已失效，请联系店员重新质检" |
| 不可撤回 | 接受或拒绝操作确认后不可撤回 |
| 状态同步 | 操作结果在 3 秒内同步至云端，云端推送至门店平板，平板同步更新核销状态 |
| 接受后流程 | 接受报价 → 系统生成核销码推送至店老板 App → 进入核销环节（由 TAB-P0-05 承接） |
| 拒绝后流程 | 拒绝报价 → 换购会话标记为 [已拒绝] → 返回 App 首页 |
**验收标准：**
- [ ] "接受报价"和"拒绝报价"按钮在报告页底部固定展示，不随页面滚动隐藏
- [ ] 点击"接受"弹出二次确认弹窗，确认后不可撤回
- [ ] 点击"拒绝"弹出二次确认弹窗，确认后返回首页
- [ ] 报价超时后按钮置灰不可操作，页面展示失效提示
- [ ] 接受后 3 秒内平板收到核销状态更新
- [ ] 拒绝后会话状态标记为 [已拒绝]

## APP-P0-04 IMEI 级下单
**优先级：** P0
**功能描述：**
用户从商品详情页点击"立即购买"，进入订单确认页。用户在订单确认页确认收货地址、支付方式等信息后，点击"提交订单"触发库存锁定，随后跳转支付。每台设备以唯一 IMEI 为粒度进行售卖和库存管理，确保一台设备不会被重复售出。
> **锁单时序说明：** 此处的"点击立即购买 → 进入订单确认页"不执行锁单。锁单发生在用户确认订单信息后点击"提交订单"时。详见 [APP-P0-07 确认订单与支付](#app-p0-07-确认订单与支付) 中的完整流程。
**业务流程：**

```
商品详情页 → 点击"立即购买"
  → 系统校验库存状态（不锁单）
    ├── 已被锁定 → 提示"该设备已被其他用户锁定，请浏览其他设备"
    ├── 已售出 → 提示"该设备已售出"
    └── 可售 → 跳转订单确认页（展示设备信息、金额）
              → 用户填写/确认收货地址、选择支付方式、选择配送方式
              → 点击"提交订单"
              → 系统锁定库存 → 跳转支付（详见 APP-P0-07）

```
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 库存校验 | 点击"立即购买"时仅校验库存状态（可售/已锁定/已售出），不执行锁定；如需锁定则提示用户 |
| 粒度 | 以唯一 IMEI 为最小售卖单元，一台设备对应一个 SKU |

## APP-P0-05 用户注册与登录
**优先级：** P0
**功能描述：**
用户通过手机号 + OTP 验证码完成注册或登录，首次注册需设置登录密码并确认用户协议。支持密码登录和验证码登录两种方式。已注册用户可通过手机号 + 密码直接登录，或通过手机号 + OTP 快捷登录。
**注册流程：**

```
启动 App → 进入登录/注册页
  → 输入手机号（自动识别国家代码，默认 +91）
  → 点击"获取验证码"
  → 系统发送 6 位 SMS OTP
  → 用户输入 OTP（3 分钟内有效）
  → 系统校验手机号：
      ├── 新用户（首次注册）→ 进入"设置密码"页面
      │     → 设置登录密码（满足密码规则）
      │     → 确认密码
      │     → 选择账号类型（v2.21）：个人账号 / 企业账号
      │     ├── 个人账号（默认）→ 无额外信息
      │     └── 企业账号 → 企业信息（必填）：
      │           → 输入/搜索门店（门店名称或门店编号，如 ST-MH-0001）
      │           → 系统从预导入的门店档案自动关联：门店名称、企业注册名、GSTIN（只读回显）
      │           → 补充账期联系人及电话（可选）
      │           → 未选择门店时"完成注册"置灰（企业账号门店为必填项）
      │     → 展示用户协议 + 隐私政策
      │     → 用户勾选"我已阅读并同意"（必勾选）
      │     → 点击"完成注册"
      │     → 账号创建成功（企业账号同时创建门店绑定 user_ent_binding，即 ROLE-ENT）
      │     → 进入 App 首页
      └── 已有账号 → 直接登录 → 进入 App 首页

```
**登录流程：**

```
App 登录页
  ├── 密码登录：
  │     → 输入手机号
  │     → 输入密码
  │     → 点击"登录"
  │     → 校验通过 → 进入 App 首页
  │     → 校验失败 → 提示"手机号或密码错误"（不区分手机号/密码具体错误）
  │
  └── 验证码登录：
        → 输入手机号
        → 点击"获取验证码"
        → 输入 OTP
        → 校验通过 → 进入 App 首页

```
**密码规则：**

| 规则项 | 说明 |
|--------|------|
| 最小长度 | 8 位 |
| 最大长度 | 20 位 |
| 复杂度要求 | 必须包含以下四类字符中的至少两类：大写字母、小写字母、数字、特殊字符（!@#$%^&*()_+-=[]{};':"\|,.<>/?） |
| 不允许内容 | 不允许包含 3 位及以上连续重复字符（如 "aaa"、"111"）；不允许包含 3 位及以上连续递增/递减数字（如 "123"、"987"） |
| 密码强度指示 | 输入密码时实时显示密码强度：弱（仅一类字符）/ 中（两类字符）/ 强（三类及以上字符），以颜色条展示 |
| 确认密码 | 设置密码时必须再次输入以确认一致，两次输入不一致时提示"两次密码输入不一致" |
| 修改密码 | 个人中心 → 账户安全 → 修改密码；需先输入原密码验证，再输入新密码；修改成功后所有已登录设备强制退出，需重新登录 |
**OTP 设计：**

| 设计点 | 说明 |
|--------|------|
| OTP 长度 | 6 位数字 |
| 有效期 | 3 分钟，过期需重新发送；倒计时展示"XX 秒后重新获取" |
| 发送渠道 | MSG91 SMS（优先），WhatsApp Business API（备选） |
| 重试次数 | 同一手机号每天最多发送 5 次 OTP；超过后提示"今日验证码发送次数已达上限，请明日再试" |
| 冷却时间 | 发送后 60 秒内不可重复发送，按钮展示倒计时 |
| 验证次数 | OTP 输入错误最多 3 次；超过后当前 OTP 失效，需重新发送 |
| 防刷机制 | 同一设备 / IP 每小时最多请求 10 次 OTP；超过后临时限制 1 小时 |
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 手机号格式 | 印度手机号，10 位数字，以 6/7/8/9 开头；自动补全 +91 国家代码 |

| 登录态持久 | 登录成功后 token 有效期 30 天，30 天内免登录；用户主动退出或修改密码后 token 失效 |
| 首次注册来源标记 | 通过线下门店 OTP 验证自动创建的账号，标记来源为"线下注册"；通过 App 自主注册的账号，标记来源为"App 注册" |
| 用户协议确认 | 首次注册时必须勾选同意《用户协议》和《隐私政策》（需分别提供可点击查看的链接），未勾选时"完成注册"按钮置灰不可点击 |
| 协议查看 | 登录页底部提供《用户协议》和《隐私政策》的查看入口，用户可在登录前阅读 |
| 多设备登录 | 同一账号可在多台设备同时登录（MVP 阶段不做踢出限制），修改密码后所有设备 token 失效 |
| 账号类型（v2.21） | 注册时选择**个人账号**（默认）或**企业账号**；企业账号的企业信息为**必填**——核心是选择门店（名称/编号搜索，自动关联预导入门店档案的企业注册名/GSTIN），选择门店后创建 `user_ent_binding` 绑定，账号即 ROLE-ENT（详见 06 §2.12.2、APP-P1-04） |

| 门店预导入前提 | 门店及其企业档案由管理员预先导入（05 SA-P0-01）——C 端注册时搜索的即这份档案；未导入的门店搜索不到、不可选 |
| 类型转换 | 个人账号后续开通企业能力为 P1（设置页入口，复用同一企业信息表单）；企业账号降级需联系管理员解绑 |
| 注销账号 | 账号一旦注销不可恢复；注销时需二次确认 + OTP 验证；注销后 30 天冷静期内可联系客服恢复 |
**验收标准：**
- [ ] 手机号输入框自动识别 +91 国家代码，格式化展示（如 +91 98765 43210）
- [ ] OTP 发送后按钮展示 60 秒倒计时，期间不可再次点击

- [ ] 新用户注册时引导设置密码，密码强度实时指示

## 账户安全与注销
**功能描述：** 用户可修改登录密码和申请注销账号。
**修改密码流程：**

```
个人中心 → 账户安全 → 修改密码

```

```
个人中心 → 账户安全 → 注销账号
  → 展示注销须知（列出注销后果）：
      - 账号数据将被永久删除且不可恢复
      - 进行中的订单将被取消
      - 未使用的优惠券/积分将作废
  → 用户确认阅读 → 输入手机号获取 OTP
  → 输入 OTP 验证身份
  → 二次确认弹窗："确定注销账号？此操作不可撤销"
  → 确认注销 → 账号标记为 [已注销]
  → 30 天冷静期 → 到期后数据物理删除

```
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 修改密码 | 需验证原密码；新密码不能与原密码相同；修改成功后所有设备 token 失效 |
| 注销条件 | 无进行中的订单（待支付/待发货/配送中/售后中）方可注销；存在进行中订单时提示"您有进行中的订单，请先完成或取消后再注销" |

| OTP 验证 | 注销需通过手机号 OTP 验证身份 |
| 不可逆 | 冷静期过后数据物理删除，不可恢复 |
**验收标准：**
- [ ] 修改密码需验证原密码，原密码错误时提示"原密码错误"

- [ ] 注销后展示成功页面 + 冷静期说明

**功能描述：**
用户从商品详情页点击"立即购买"后进入订单确认页，在此确认/选择收货地址、查看商品详情和金额明细、选择配送方式和支付方式，最后点击"提交订单"完成库存锁定并进入支付环节。支付支持 Razorpay UPI，支付失败时支持重试。
> **锁单时序修正（关键）：** 原方案中"立即购买"即锁单的设计存在缺陷——用户在未确认收货地址、支付方式等必要信息前即占用库存。修正后流程为：立即购买 → 进入订单确认页（不锁单）→ 用户确认所有信息 → 点击"提交订单" → 系统锁单（5 分钟）→ 进入支付。此修正确保锁单发生在用户已完成所有信息确认、具备支付意愿的时刻。
**完整流程图：**

```
商品详情页
  → 点击"立即购买"
  → 库存状态校验（仅校验，不锁单）
      ├── 已锁定/已售出 → 提示不可购买
      └── 可售 → 进入订单确认页
            │
            ├── 确认/选择收货地址
            ├── 查看商品信息（设备图、型号、成色、IMEI后四位、单价）
            ├── 查看金额明细（商品金额 + 配送费 + 税费 = 实付金额）
            ├── 选择配送方式（标准配送/快速配送）
            └── 选择支付方式（UPI / 已绑定UPI / 银行卡）
            │
            → 点击"提交订单"
            → [新增] 校验配送区域（Pincode Serviceability）
                  ├── ✅ 可配送 → 继续
                  └── ❌ 不可配送 → 提示"该地区暂不支持配送，请更换收货地址"
                                    → 阻止提交，不锁定库存，不生成订单
            → 系统锁定 IMEI 库存（5 分钟锁定）
            → 生成订单（状态：待支付）
            → 唤起 Razorpay UPI 支付
                  │
                  ├── 支付成功 → 跳转支付成功页（展示订单号）
                  │              → 订单状态变更为"待发货"
                  │
                  ├── 支付失败 → 展示支付失败页
                  │              → 展示失败原因
                  │              → 提供"重新支付"按钮
                  │              → 锁定持续（5 分钟内可重试）
                  │
                  └── 超时未支付 → 5 分钟倒计时归零
                                   → 自动取消订单
                                   → 释放 IMEI 锁定
                                   → 推送通知"订单已超时取消"
                                   → 设备恢复可售

```

| 商品信息区 | 设备主图缩略图、品牌型号、成色等级标签、IMEI 后四位、存储容量、颜色 |

**支付失败处理：**

| 失败场景 | 处理方式 |
|----------|----------|
| UPI App 支付失败 | 展示失败原因（银行返回的错误描述），提供"重新支付"按钮，锁单时间继续倒计时 |

| 规则项 | 说明 |

## APP-P0-08 订单取消
**优先级：** P0
**功能描述：**
用户可在订单不同状态下发起取消操作。待支付订单取消时释放库存锁定；待发货订单取消时按规则退款；已发货订单取消需先拒收或退回后再处理。不同订单状态对应不同的取消规则和退款策略。
**取消规则（按订单状态）：**

| 订单状态 | 可取消 | 库存处理 | 退款规则 |
|----------|--------|----------|----------|
| 待支付 | 是 | 立即释放 IMEI 锁定，设备恢复可售 | 无需退款（未支付） |
| 待发货 | 是 | 设备重新上架为可售 | 全额退款（商品金额 + 配送费 + 税费），原路退回 |
| 配送中 | 否（需先拒收） | 设备标记为退回中，退回原仓库重新质检后上架 | 拒收后退款：退回商品金额 + 税费，扣除往返运费 |
| 已签收 | 否（走售后流程） | — | 不适用（需走售后申请，见 APP-P0-09） |
| 已完成（超过 7 天） | 否 | — | 不适用 |

> **授信支付（企业）退款口径**（联动 06 PRD CR-08）：授信单退款**不走 Razorpay 原路退回**（平台未实际收款），改为按阶段回补门店额度——①已支付**未发货**取消 → 全额回补冻结额度（商品金额 + 配送费 + 税费，未产生运费故全额）；②**配送中/已发货**拒收 → 回补已用额度 = 商品金额 + 税费 − 往返运费（与个人单配送中拒收同口径扣运费）；③已结算后退款 → 生成额度贷记单（credit_note）增加可用额度。原则：未产生运费前取消全额回补、已产生运费后取消扣除运费，平台不承担已产生的物流成本。

**取消流程：**

```
订单详情页 → 点击"取消订单"
  ├── 待支付订单：
  │     → 弹窗确认："确定取消订单？取消后该设备将被释放"
  │     → 确认 → 取消订单 → 释放库存 → 状态变为"已取消"
  │
  ├── 待发货订单：
  │     → 弹窗确认："确定取消订单？将全额退款至您的原支付方式"
  │     → 确认 → 取消订单 → 设备重新上架
  │     → 系统发起退款（原路退回）
  │     → 展示退款进度："预计 5-7 个工作日到账"
  │     → 状态变为"已取消（退款中）"
  │
  └── 配送中订单：
        → 提示"订单已在配送中，不可直接取消"
        → 提供操作指引："您可在收到商品时拒收，或签收后走售后流程"
        → 展示"拒收操作说明"和"联系客服"入口

```

**配送中拒收退回流程（退回入库）：**

```
用户当面拒收 / 物流派送失败退回
  → 订单状态 → [退回中]
  → 设备退回原仓库，交库管重新质检（检查防拆标签是否完整、有无人为拆机/损坏）
  → 标签完好且与出库记录一致 → 设备重新上架为可售
  → 标签损坏 / 设备异常 → 进入争议处理（部分退款/拒退）
  → 系统发起退款：退回商品金额 + 税费，扣除往返运费
```

**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 取消入口 | 订单详情页底部"取消订单"按钮（仅可取消的订单状态展示） |
| 二次确认 | 所有取消操作均需弹窗二次确认，展示取消后果说明 |
| 库存释放 | 待支付订单取消后立即释放库存，秒级生效 |
| 退款时效 | 待发货订单取消后，退款在 5-7 个工作日内原路退回（Razorpay 处理时效） |
| 退款方式 | 个人支付（UPI / 银行卡）原路退回；**授信支付（企业）按 CR-08 回补门店额度，不走原路退回**（见上方「授信支付退款口径」） |
| 退款通知 | 退款发起和到账时分别推送 App 通知 |
| 取消原因 | MVP 阶段不强制要求选择取消原因；P2 阶段加入取消原因收集用于分析 |
| 配送中订单 | 不可直接取消；引导用户拒收或走售后；提供联系客服入口 |
| 已签收订单 | 不可取消；引导走售后申请流程（见 APP-P0-09） |
**验收标准：**
- [ ] 待支付订单取消后库存立即释放，设备在商城中恢复可售
- [ ] 待发货订单取消后设备重新上架，系统发起全额退款
- [ ] 退款金额 = 商品金额 + 配送费 + 税费（全额退）
- [ ] 退款进度在订单详情中展示："已发起退款 → 银行处理中 → 已到账"
- [ ] 配送中订单点击"取消订单"时提示不可取消并给出操作指引
- [ ] 已签收/已完成订单不展示"取消订单"按钮
- [ ] 所有取消操作均有二次确认弹窗
- [ ] 退款到账后推送通知"您的订单退款已到账"
- [ ] 授信支付订单未发货取消时，冻结额度全额回补（商品金额 + 配送费 + 税费）
- [ ] 授信支付订单配送中拒收时，已用额度回补 = 商品金额 + 税费 − 往返运费（扣除运费）

## APP-P0-09 售后申请
**优先级：** P0
**功能描述：**
用户签收设备后发现商品存在与描述不符的质量问题，或商品在运输过程中出现损坏，可通过 App 提交售后申请。售后类型包括退货退款、换货和维修（P2）。用户需选择售后原因、上传举证照片，并选择退货物流方式。售后流程覆盖申请提交、审核、上门取件/自行寄回、退款/换货、售后状态追踪的完整闭环。
**售后类型：**

| 售后类型 | 适用条件 | 说明 |
|----------|----------|------|
| 退货退款 | 商品与描述严重不符、商品存在未披露的功能性缺陷、运输损坏 | 退回商品 → 全额退款（含配送费） |
| 换货 | 商品存在可修复的质量问题、发错型号/颜色/存储容量 | 退回商品 → 发换同型号同级设备 |
| 维修（P2） | 商品签收后 7 天内出现非人为功能性故障 | 寄修或上门维修 |
**售后申请流程：**

```
订单详情页 → 点击"申请售后"
  → 选择售后类型：退货退款 / 换货
  → 选择售后原因（从预设列表中选择）
  → 上传举证材料（照片/视频）
  → 填写问题描述（可选，最多 500 字）
  → 选择退货物流方式：上门取件 / 自行寄回
  → 确认退款方式（原路退回 / 退回至钱包余额）
  → 提交售后申请
  → 系统生成售后单号
  → 进入审核流程

```
**退货原因分类（预设，用户单选）：**

| 原因类别 | 具体原因选项 |
|----------|-------------|
| 外观与描述不符 | 成色等级与描述不符、有明显未披露的划痕/磕碰、屏幕有未披露的划痕/坏点、机身有未披露的变形/凹陷 |
| 功能性问题 | 电池续航严重不足（低于检测值 20% 以上）、屏幕触摸失灵/断触、摄像头无法使用/成像异常、扬声器/麦克风异常、按键失灵、Face ID/Touch ID 不可用（描述中未说明）、无法开机/频繁重启、存储容量与描述不符 |
| 发错商品 | 型号错误、颜色错误、存储容量错误 |
| 运输损坏 | 包装完好但设备损坏、包装破损导致设备损坏 |
| 配件缺失 | 描述中包含的配件未收到 |

## APP-P0-11 下单配送区域校验
**优先级：** P0
**功能描述：**
用户在提交订单前，系统校验收货地址的 pincode 是否在发货仓库的物流覆盖范围内。校验在用户选择/修改收货地址时自动触发（防抖 500ms），实时反馈可配送/不可配送；不可配送时阻止提交订单并引导更换地址。本功能为 APP-P0-07 确认订单页的下单前置门禁，下单流程闭环的必要条件。

> **编号说明：** 本功能原以"下单配送区域校验"记入 v2.0 更新日志并标注 APP-P0-11，但正文规则此前一直并入 APP-P0-07 章节描述，未独立成节。本次补齐为独立 P0 章节，APP-P0-07 保留订单确认页内的流程性描述并交叉引用本章节。

**配送区域状态展示：**

| 状态 | 展示 |
|------|------|
| 可配送 | 地址下方展示 ✅ 支持配送（绿色）+ 预计 3-5 个工作日送达 |
| 不可配送 | 地址下方展示 ❌ 该地区暂不支持配送（红色）+ "请更换收货地址"引导，"提交订单"按钮置灰 |
| 校验中 | 地址下方展示校验中占位（选择/修改地址后触发） |
| 校验失败 | 展示"配送校验失败，请重试"+ 重试入口，按钮临时置灰 |

**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 校验时机 | 提交订单前必须校验；在用户选择/修改收货地址时自动触发（防抖 500ms），结果 1 秒内更新 |
| 校验数据源 | 主数据源：服务端本地 pincode 覆盖表（每日凌晨同步自 Delhivery）；辅助数据源：Delhivery Pincode Serviceability API 实时查询；API 不可用时降级为本地 DB 查询，记录告警 |
| 不可配送处理 | 阻止提交订单（按钮置灰）并引导用户更换地址，不提供"强制下单"入口 |
| 校验失败降级 | 网络问题导致校验失败/超时时，展示重试入口，按钮临时置灰；不做"放行"处理，避免产生无法履约的订单 |
| 结果缓存 | 用户地址列表页中，之前校验过的地址保留配送状态缓存，避免重复校验 |
| B2B 拆单场景 | 多仓库发货时，每个子订单的收货地址需分别校验 pincode（若主订单含 N 个仓库，任一仓库不可配送则该子订单对应的设备不可购买） |
| 与地址校验区分 | pincode 六位格式校验与州/市匹配（APP-P0-06 地址管理）为**格式校验**，本章节为**物流覆盖范围校验**，二者独立且均需通过 |

**输入：** 收货地址（含 6 位 pincode）+ 发货仓库
**输出：** 配送可行性（可配送 + 预计送达时间 / 不可配送）

**验收标准：**
- [ ] 选择/修改收货地址后 1 秒内自动校验配送区域，展示 ✅ 或 ❌ 结果
- [ ] pincode 不可配送时，"提交订单"按钮置灰，提示"该地区暂不支持配送，请更换收货地址"
- [ ] pincode 可配送时，展示预计送达时间（如"预计 3-5 个工作日送达"）
- [ ] 校验失败/超时（网络问题）时降级处理：展示"配送校验失败，请重试"+ 重试入口，按钮临时置灰
- [ ] 用户地址列表页中，之前校验过的地址保留配送状态缓存（避免重复校验）
- [ ] B2B 多仓库拆单场景下，逐子订单校验 pincode，不可配送的子订单设备不可购买
- [ ] 配送区域校验（本章节）与 pincode 格式/州匹配校验（APP-P0-06）分别生效，互不替代

**采集项与估价的关系：**
- 参与初步估价的采集项及其与定价引擎扣款编码的映射，见服务端 PRD `06_云端中台_服务端_PRD.md` §3.1.2.1（映射表由运营在配置中心维护）
- **不参与估价**的采集项：`是否在保`（仅随预约单同步门店，质检后作为商品"是否在保"标签展示）、`回收前置条件自检`（7 项，用于预约准入判断，见下方「准入自检规则」）；均不影响预估价与正式回收价
- 注意自检项中的"能否退出登录账号"指账号退出状态（能否退出账号），不是使用年限；平台不采集使用年限
**准入自检规则：**

## APP-P1-03 同城优先推荐
**优先级：** P1
**功能描述：**
商城首页和设备列表页优先展示与用户同城的仓库货源，缩短物流时效。同城商品标注"同城"标签，排序权重高于非同城商品。此逻辑适用于默认排序和搜索结果排序。
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 城市获取 | 见下方「城市获取与定位权限」；用户可在城市选择器或设置页手动选择/修改城市 |
| 同城定义 | 设备所在仓库城市 = 用户当前城市 |
| 同城标签 | 同城设备在商品卡片上展示"同城"标签（绿色/蓝色徽章） |
| 排序策略 | 默认排序：同城设备置顶（按入库时间 FIFO）→ 非同城设备（按入库时间 FIFO） |
| 覆盖范围 | 仅影响默认排序和搜索结果的自然排序；用户主动选择其他排序方式（如价格排序）时同城权重不生效 |
| 同城无结果 | 同城无库存时自动展示全国范围的设备列表，顶部提示"您所在城市暂无库存，为您展示全国设备" |
| 当前城市取值 | 三选一：①用户手动选择的城市（**优先级最高**，选择后不再被定位结果覆盖）②定位到的城市 ③"全国"（未定位且未手动选择） |

## 城市获取与定位权限

**定位请求时机：** 不在 App 冷启动时请求。用户**首次进入商城首页或换购门店选择页**时，先展示用途说明弹窗（`开启定位可优先展示同城货源，配送更快` + 「暂不开启」/「开启定位」），用户点「开启定位」后才触发系统权限弹窗。用户点「暂不开启」则跳过系统弹窗，直接进入下方「定位被拒绝」分支。

**分支 A：用户同意定位**

```
取经纬度 → 逆地理编码为城市（精度到城市级，5 秒超时）
  ├── 定位城市 ∈ 已开通城市列表
  │     → 设为当前城市；同城优先生效；商品卡展示"同城"标签
  ├── 定位城市 ∉ 已开通城市列表
  │     → 当前城市仍显示该城市名 + 「暂未开通」标签（不静默改成别的城市）
  │     → 商品列表按全国展示，不做同城置顶，不展示同城标签
  │     → 顶部横幅"您所在的城市暂未开通服务，已为您展示全国设备 · 选择城市"
  │     → 门店列表页展示空态 + 「就近推荐已开通城市」（按距离升序取最近 3 个）
  └── 定位失败/超时 → 降级 IP 定位；仍失败 → 按分支 B 处理
```

**分支 B：定位被拒绝**

| 规则项 | 说明 |
|--------|------|
| 不再重复请求 | 用户拒绝后**不再弹系统权限弹窗**（含"拒绝且不再询问"），避免骚扰 |
| 首次引导 | 首次拒绝后自动弹出**城市选择底部弹层**，引导用户手动选一个城市 |
| 未选择前的默认值 | 当前城市 = **"全国"**；商品按全国展示；不做同城优先；不展示同城标签 |
| 常驻入口 | 商城首页顶部城市选择器常驻，显示"全国"或已选城市名 |
| 二次开启引导 | 用户在城市弹层内点「使用我的位置」，而系统权限已被永久拒绝 → 展示引导文案 + 「前往系统设置」入口（跳转 App 系统设置页） |

**分支 C：定位能力不可用**（设备无定位服务 / 系统隐私设置禁用）→ 同分支 B 处理，引导文案改为"当前设备无法获取位置，请手动选择城市"。

## APP-P2-02 评价系统
**优先级：** P2
**功能描述：**

| 电池健康度准确性 | 星级（1-5） | 实际电池健康度与展示值的偏差 |

| 文字评价 | 文本（可选，最多 500 字） | 补充评价内容 |
| 图片评价 | 图片（可选，最多 3 张） | 上传实拍照片 |
**门店服务评价（换购完成后）：**

| 评价维度 | 类型 | 说明 |
|----------|------|------|
| 综合评分 | 星级（1-5） | 对门店服务的整体评分 |
| 店员服务态度 | 星级（1-5） | 店员服务态度评价 |
| 质检专业度 | 星级（1-5） | 店员质检操作的专业程度 |

| 评价统计 | 商品详情页展示该型号设备的评价均分和数量（仅限该 IMEI ？→ 同型号同成色等级的设备汇总展示） |

## APP-P2-04 收藏/心愿单
