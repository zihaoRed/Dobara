# 05 — 门店综合 App PRD（店老板 + 库管 + DB 三合一） | Unified Store App PRD
> 面向：iOS + Android 移动端开发 / QA  
> 平台：iOS + Android  
> 使用角色：店老板 / 库管 / DB（财务）— 同一 App，按角色权限显示不同模块

## 一、设计理念
## 1.1 为什么合并

| 维度 | 三个独立 App | 一个统一 App |
|------|:---:|:---:|
| 开发维护 | 3 份代码库，3 条 CI/CD | 1 份代码库，模块化加载 |
| 发布更新 | 3 个 App Store 上架 | 1 个 App |
| 多角色用户 | 装 3 个 App | 装 1 个，切换角色/视图 |
| 账号管理 | 3 套登录 | 1 套登录，权限控制可见模块 |
| 运营管理 | 后台 3 套角色配置 | 1 套权限矩阵，勾选即可 |
**核心原则**：一个 App，一套代码，角色决定界面。运营后台开通账号时勾选角色权限，App 动态加载对应模块。

## 二、账号与登录
## UA-P0-01 统一登录
**优先级：** P0
**功能描述：**
所有角色使用同一登录入口。输入手机号 + 密码（或 OTP）登录，服务端返回该账号的角色列表和对应权限。若该账号只有一个角色，直接进入该角色视图；若有多个角色，展示角色选择页。
**登录流程：**

```
打开 App → 登录页
  → 输入手机号 + 密码（或OTP）
  → 服务端验证 → 返回：
      {
        user_id, name, phone,
        roles: [
          { role: "owner", store_id: "ST001", store_name: "Mumbai Central" },
          { role: "warehouse", warehouse_id: "WH002", warehouse_name: "Mumbai Main" }
        ]
      }
  → 单角色 → 直接进入该角色首页
  → 多角色 → 展示角色选择页（选择后进入对应模块视图）

```
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 登录方式 | 手机号 + 密码（主）；手机号 + OTP（备用） |
| 角色返回 | 服务端根据账号配置的角色列表，携带对应的门店/仓库信息 |
| 多角色切换 | App 内左上角头像 → "切换角色"，无需重新登录 |
| 权限即时生效 | 运营后台修改权限后，App 下次切换角色时重新拉取权限列表 |
| 会话超时 | 30 分钟无操作自动退出，需重新登录 |
| 设备绑定 | 一个账号最多同时在 3 台设备登录；运营后台可强制踢出 |
**验收标准：**
- [ ] 手机号+密码登录成功，服务端返回角色列表
- [ ] 单角色直接进入对应首页，多角色展示选择页
- [ ] App 内切换角色无需重新登录
- [ ] 权限即时生效
- [ ] 30 分钟超时自动退出

## 三、店老板角色模块（原 OWN）
## OWN-P0-01 换购价格录入
**优先级：** P0
**功能描述：**
用户接受报价后，云端推送抵扣金额至店老板 App（统一 App 的店老板角色视图）。店老板仅负责录入新机售价和消费者实付金额，系统实时校验公式（新机售价 − 抵扣 = 实付），校验通过后提交。核销确认由用户在 C 端 App 完成，店老板不参与确认环节。
**操作流程：**

```
收到推送"新的换购待处理"
  → 点击进入价格录入页
  → 查看旧机抵扣金额（只读）
  → 录入新机售价 + 消费者实付金额
  → 系统实时校验：新机售价 − 抵扣 ?= 实付
  → 校验通过 → 提交（店老板操作结束）
  → 用户在 App 确认核销后收到完成通知

```
**验收标准：**
- [ ] 用户接受报价后 3 秒内收到推送通知
- [ ] 录入金额后实时校验公式
- [ ] 校验不通过时展示差值并阻止提交
- [ ] 校验通过后提交，店老板操作完成
- [ ] 用户确认核销后收到完成通知
## OWN-P0-02 店员管理
**优先级：** P0
**功能描述：**
店老板在 App 内管理本门店的店员账号，包括添加店员、移除店员、查看店员列表。店员账号用于平板质检工具的登录和操作。
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 添加店员 | 输入店员手机号 → 设置初始密码 → 选择角色 → 发送邀请 SMS |
| 移除店员 | 移除后该店员无法登录平板，历史记录保留 |
| 店员列表 | 姓名、手机号、角色、最近活跃时间、本月质检数量 |
| 权限隔离 | 店老板仅可管理本门店店员 |
**验收标准：**
- [ ] 店老板可添加/移除店员账号
- [ ] 移除后店员即时无法登录平板
- [ ] 店员列表展示基本信息和活跃状态
## OWN-P0-03 门店营收查看
**优先级：** P0
**功能描述：**
店老板查看本门店的营收数据概览：本月回收量、总抵扣金额、换购成交笔数、运营调整率。数据每日凌晨自动更新。
**验收标准：**
- [ ] 营收数据每日自动更新
- [ ] 店老板仅可查看本门店数据

## 四、库管角色模块（原 WH）
## WH-P0-01 设备入库确认
**优先级：** P0
**功能描述：**
仓库操作员（库管角色）接收门店发来的旧机，通过扫描设备包装上的条码确认入库。系统自动关联质检环节已上传的影像和硬件数据。
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 入库方式 | 扫码入库（扫描 session_id 或 IMEI 条码） |
| 影像复用 | 自动关联质检影像，无需重新拍照 |
| 入库校验 | 校验设备状态为核销已完成 |
| 异常处理 | 状态不符时提示具体原因 |
**验收标准：**
- [ ] 扫码后 2 秒内完成入库确认
- [ ] 入库后设备状态自动变更为"待上架申请"
- [ ] 状态不符时明确提示不可入库原因
## WH-P0-00 仓库翻新质检
**优先级：** P0
**功能描述：**
设备入库后，库管判断是否需要翻新。如需翻新，在 App（库管角色）执行完整质检流程（拍照、硬件检测、外观点检），上传覆盖原数据，系统重新计算成色与价格。
**验收标准：**
- [ ] 入库后可选择"需要翻新"或"直接通过"
- [ ] 翻新质检流程完整可用
- [ ] 翻新后系统自动重算价格
## WH-P0-02 出库任务列表
**优先级：** P0
**功能描述：**
展示待出库任务列表，B2C 订单优先。每条任务展示设备信息、订单号、收件地址。支持按订单号或 IMEI 搜索。
**验收标准：**
- [ ] B2C 订单标记"优先"
- [ ] 支持搜索，已完成任务自动移出列表
## WH-P0-03 扫码核销 IMEI
**优先级：** P0
**功能描述：**
库管从货架取机后，扫描设备 IMEI 条码进行出库核销。校验 IMEI 与出库任务匹配，防止错发。核销后可调用蓝牙打印机打印面单。
**验收标准：**
- [ ] 匹配 IMEI 展示设备信息确认
- [ ] 不匹配 IMEI 告警并阻止出库
- [ ] 已出库 IMEI 重复扫描时提示
## WH-P0-04 打印快递面单
**优先级：** P0
**功能描述：**
IMEI 核销成功后，系统自动生成面单数据并通过蓝牙调用标签打印机打印。支持手动重打。
**验收标准：**
- [ ] IMEI 核销后一键打印面单
- [ ] 面单信息正确完整
- [ ] 支持手动重打并记录原因
## WH-P0-05 库存查询
**优先级：** P0
**功能描述：**
库管按 IMEI、品牌、机型、成色等多维度查询本仓库库存，查询响应 < 3 秒。
**验收标准：**
- [ ] 多条件组合查询，响应 < 3 秒
- [ ] 点击设备可查看完整详情
## WH-P1-01 批量出库
**优先级：** P1
**功能描述：**
B2B 批量订单逐台扫码核销后，一键批量确认并批量打印面单，展示出库进度。
## WH-P2-01 库存盘点
**优先级：** P2
**功能描述：**
按周期或手动发起盘点，逐台扫码确认实物，生成差异报告。

## 五、DB 角色模块（原 DB）
## DB-P0-01 授信订单结算
**优先级：** P0
**功能描述：**
DB 查看所有通过授信支付的 B2B 订单（已发货），发起结算。门店付款后 DB 确认收款，系统释放额度。
**待结算列表字段：** 门店名称、订单号、金额、下单/发货时间、逾期状态
**验收标准：**
- [ ] 逾期订单红色标记
- [ ] 支持多选批量结算
- [ ] 确认收款后额度自动释放
## DB-P0-02 门店对账
**优先级：** P0
**功能描述：**
按期生成门店对账单（回收明细 + B2B 采购明细 + 净结算额），支持导出 PDF/Excel。
**验收标准：**
- [ ] 按门店+日期范围生成
- [ ] 支持导出 PDF/Excel
- [ ] 数据与系统记录一致
## DB-P0-03 换购凭证审核
**优先级：** P0
**功能描述：**
DB 抽查换购凭证，核对旧机新机信息和金额一致性。异常标记"待核查"，推送至店老板 App。
**验收标准：**
- [ ] 按门店/日期范围查询凭证
- [ ] 支持标记"异常"并填写原因
- [ ] 异常标记后推送店老板
## DB-P1-01 佣金核算
**优先级：** P1
**功能描述：**
按月自动生成门店佣金结算单。佣金公式可配置（P2）。

## 六、通用功能
## UA-P0-02 角色切换
**优先级：** P0
**功能描述：**
多角色用户可在 App 内随时切换角色视图，无需重新登录。切换后展示对应角色的首页和数据。
**交互：** 左上角头像 → "切换角色" → 选择目标角色 → 页面刷新为目标角色首页
**验收标准：**
- [ ] 切换角色 < 1 秒完成
- [ ] 各角色数据隔离正确
- [ ] 切换后通知角标按角色独立
## UA-P0-03 通用设置
**优先级：** P0
**功能描述：**
统一的设置页：语言切换（英语/印地语）、通知偏好、关于/版本信息、缓存清理、用户协议、隐私政策、退出登录。
**验收标准：**
- [ ] 语言切换即时生效
- [ ] 退出登录清除本地缓存

## 七、模块可见性配置
运营后台（CLOUD-P0-11）配置权限后，App 按以下规则加载模块：

| 运营后台勾选角色 | App 可见模块 |
|------|------|
| 店老板 | 核销录入、店员管理、营收查看、B2B 采购 |
| 库管 | 入库确认、翻新质检、出库任务、扫码核销、面单打印、库存查询、批量出库、库存盘点 |
| DB | 授信结算、门店对账、凭证审核、佣金核算 |
| 店老板 + 库管 | 上述两个角色模块全部可见，首页默认上次使用的角色 |
| 店老板 + DB | 同上 |
| 全部三个角色 | 全部模块可见 |
