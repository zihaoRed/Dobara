## 一、设计理念
## 1.1 为什么合并

| 维度 | 三个独立 App | 一个统一 App |
|------|:---:|:---:|
| 开发维护 | 3 份代码库，3 条 CI/CD | 1 份代码库，模块化加载 |
| 发布更新 | 3 个 App Store 上架 | 1 个 App |
| 多角色用户 | 装 3 个 App | 装 1 个，切换角色/视图 |
| 账号管理 | 3 套登录 | 1 套登录，权限控制可见模块 |
| 运营管理 | 后台 3 套角色配置 | 1 套权限矩阵，勾选即可 |
**核心原则**：一个 App，一套代码，角色决定界面。运营后台开通账号时勾选角色权限，App 动态加载对应模块。

### 2.3 完整账号链路

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 1.SA在后台 │→  │ 2.SA创建  │→  │ 3.SA创建  │→  │ 4.店老板  │→  │ 5.店员   │

Step 1: 系统部署 → 数据库初始化脚本自动创建
  ├── ROLE-SA 系统管理员账号（初始密码在部署时注入环境变量）
  ├── 7 个预置角色（ROLE-SA/OPS/OWN/CLK/WH/DB/ENT）
  └── 预置权限矩阵（各角色的默认权限集）
  → SA 首次登录 → 强制修改密码 → 进入运营后台

Step 2: SA 创建门店/仓库（详见运营后台 PRD CLOUD-P0-11）

  → 仓库编码自动按州生成（如 WH-MH-0001）

Step 3: SA 创建店老板账号
  → 输入手机号 → 选择角色 ROLE-OWN → 绑定门店 ST-MH-0001

Step 4: 店老板添加店员（详见下方 OWN-P0-02）

Step 5: 店员登录平板（详见平板 PRD TAB-P0-12）

## 三、账号与登录

## UA-P0-01 统一登录
**优先级：** P0
**功能描述：**
所有角色使用同一登录入口。输入手机号 + 密码（或 OTP）登录，服务端返回该账号的角色列表和对应权限编码。若该账号只有一个角色，直接进入该角色视图；若有多个角色，展示角色选择页。
**登录流程：**

```
打开 App → 登录页（展示 Dobara 品牌 Logo）
  → 输入手机号（印度 +91 前缀固定展示，输入 10 位数字）
  → 输入密码（支持切换为 OTP 登录）
  → 点击"登录"
  → 服务端验证：
      ├── 账号不存在 → "账号不存在，请联系管理员开通"
      ├── 账号已禁用 → "账号已被停用，请联系管理员"
      ├── 密码错误 → "密码错误，剩余重试 N 次"（5 次锁定 15 分钟）
      ├── 账号待激活（首次登录）→ "请先设置您的密码"→ 进入密码设置页
      └── 验证通过 → 返回完整登录响应
```

**登录页面的三种入口：**

| 入口 | 说明 |
|------|------|
| 密码登录（默认） | 手机号 + 密码，登录按钮 |
| OTP 登录（切换） | 手机号 → 发送 OTP（6位/3分钟）→ 输入 OTP → 验证通过 |
| 忘记密码 | "忘记密码？"→ 输入手机号 → OTP 验证 → 设置新密码 → 重新登录 |

**首次登录——强制激活流程：**

```
SA/店老板创建账号后，系统发送邀请 SMS（含临时密码）
  → 用户下载 App，输入手机号 + 临时密码
  → 服务端检测 account_status = "pending_activation"
  → 强制跳转密码设置页：
      ├── 输入新密码（8-20 位，至少含大写字母+数字两类字符）
      ├── 确认新密码
      ├── 勾选同意用户协议和隐私政策
      └── 点击"激活账号"
  → 服务端：
      ├── 更新 password_hash
      ├── 更新 account_status = "active"
      ├── 记录 activated_at 时间戳
      └── 返回完整登录响应（含角色+权限）
  → App 进入角色首页
```

**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 登录方式 | 手机号 + 密码（主）；手机号 + OTP（备用，3分钟有效） |
| 密码规则 | 8-20 位，至少含大写字母 + 数字两类字符；禁止与手机号相同 |
| 密码修改 | 需输入旧密码 + 新密码 + 确认新密码；修改后所有设备 token 失效，需重新登录 |
| 登录失败锁定 | 连续 5 次密码错误 → 锁定 15 分钟；锁定期间"登录"按钮置灰 + 展示倒计时 |
| 角色返回 | 服务端根据 `user_role_assignment` 表返回该账号的所有已启用角色及对应门店/仓库信息 |
| 多角色切换 | App 内左上角头像 → "切换角色"，无需重新登录（详见 UA-P0-02） |
| 权限即时生效 | 运营后台修改权限后，用户下次切换角色或重新登录时权限生效 |
| 会话超时 | 30 分钟无操作自动退出；所有角色共享同一超时计时器 |
| 设备绑定 | 一个账号最多同时在 3 台设备登录；运营后台可强制踢出特定设备 |
| JWT Token | 每个角色独立 JWT；payload 中含 `role_code`、`org_id`、`permissions[]`、`exp` |
| Token 刷新 | Token 过期前 5 分钟自动刷新；刷新失败需重新登录 |

**忘记密码流程：**

```
App 登录页 → 点击"忘记密码？"
  → 输入手机号（必须与注册手机号一致）
  → 点击"发送验证码"
  → 系统发送 6 位 OTP（3 分钟有效）
  → 输入 OTP → 验证通过
  → 进入设置新密码页：
      ├── 输入新密码（8-20 位，至少两类字符）
      ├── 确认新密码
      └── 点击"确认修改"
  → 服务端更新密码 → 所有设备 token 失效
  → 返回登录页："密码修改成功，请使用新密码重新登录"
```

**验收标准：**
- [ ] 手机号+密码登录成功，服务端返回角色列表 + 权限编码
- [ ] 手机号格式校验：10 位印度手机号，非法格式即时提示
- [ ] 单角色直接进入对应首页，多角色展示选择页
- [ ] 连续 5 次密码错误锁定 15 分钟，展示倒计时
- [ ] 首次登录（临时密码）强制跳转密码设置页 + 协议确认
- [ ] 临时密码仅可使用一次（登录成功后失效）
- [ ] 忘记密码：OTP 验证通过后可设置新密码，旧密码立即失效
- [ ] 密码修改后所有设备 token 失效，需重新登录
- [ ] App 内切换角色无需重新登录（详见 UA-P0-02）
- [ ] 权限即时生效
- [ ] 30 分钟超时自动退出
- [ ] 账号被禁用后 5 分钟内当前会话自动登出
- [ ] Token 过期前 5 分钟自动刷新

## 三、店老板角色模块（原 OWN）
## OWN-P0-01 换购价格录入
**优先级：** P0
**功能描述：**
用户接受报价后，云端推送抵扣金额至店老板 App（统一 App 的店老板角色视图）。店老板仅负责录入新机售价和消费者实付金额，系统实时校验公式（新机售价 − 抵扣 = 实付），校验通过后提交。核销确认由用户在 C 端 App 完成，店老板不参与确认环节。
**操作流程：**

```
收到推送"新的换购待处理"
  → 点击进入价格录入页
  → 查看旧机抵扣金额（只读）
  → 录入新机售价 + 消费者实付金额
  → 系统实时校验：新机售价 − 抵扣 ?= 实付
  → 校验通过 → 提交（店老板操作结束）
  → 用户在 App 确认核销后收到完成通知

```
**验收标准：**
- [ ] 用户接受报价后 3 秒内收到推送通知
- [ ] 录入金额后实时校验公式
- [ ] 校验不通过时展示差值并阻止提交
- [ ] 校验通过后提交，店老板操作完成
- [ ] 用户确认核销后收到完成通知
## OWN-P0-02 店员管理
**优先级：** P0
**功能描述：**
店老板在 App 内管理本门店的店员账号，包括添加店员、移除店员、查看店员列表。店员账号用于平板质检工具的登录和操作。添加店员时采用邀请制——店老板输入店员手机号后系统发送邀请 SMS，店员通过邀请链接下载 App 并激活账号。
**添加店员流程：**

```
店老板登录 → "店员管理" → 点击"添加店员"
  → 输入店员手机号（10 位印度手机号，以 6/7/8/9 开头）
  → 选择店员角色：店员(ROLE-CLK) / 库管(ROLE-WH)
  → （若选库管）选择绑定仓库
  → 点击"发送邀请"

服务端校验：
  ├── 该手机号是否已是本门店店员？→ 是 → 提示"该员工已在本门店"
  ├── 店员数量是否达上限？→ 是（默认 10 人/店）→ 提示"店员数量已达上限，请联系管理员"
  └── 全部通过 →
        ├── 若该手机号已有平台账号：
        │     → 在 user_role_assignment 表中新增记录
        │     → 状态 = "active"（直接激活，无需激活）
        │     → 发送通知 SMS
        └── 若该手机号无平台账号：
              → 创建 user 记录
              → 生成临时密码（8 位随机，含大小写+数字）
              → 在 user_role_assignment 表中新增记录
              → 状态 = "pending_activation"
              → 发送邀请 SMS（含临时密码 + App 下载链接）
              → 店员首次用临时密码登录 → 强制激活流程（同 UA-P0-01）
```

## UA-P0-04 账号安全与恢复
**优先级：** P0
**功能描述：**
提供密码修改、手机号更换、账号注销等账号安全功能，以及异常场景下的账号恢复机制。
**密码修改：**

```
App 设置 → "修改密码"
  → 输入旧密码
  → 输入新密码（8-20 位，至少含大写字母 + 数字）
  → 确认新密码
  → 点击"确认修改"
  → 服务端更新密码 → 所有设备 token 失效
  → 提示"密码已修改，请重新登录"
  → 返回登录页
```

**换绑手机号（需联系管理员）：**

```
店员 → 告知店老板 → 店老板联系 SA
SA 在运营后台：
  → 找到该用户的账号
  → 点击"更换手机号"
  → 输入新手机号 → 系统向新手机号发送 OTP 验证
  → 验证通过 → 更新 phone 字段
  → 旧手机号自动解绑
  → 系统向新旧手机号同时发送通知 SMS
```

**安全设置：**

| 功能 | 说明 |
|------|------|
| 修改密码 | 需旧密码验证；修改后所有设备 token 失效 |
| 登录设备管理 | 查看当前已登录的设备列表（设备类型、登录时间、IP）；支持单设备远程登出 |
| 安全通知 | 新设备登录、密码修改、手机号更换等敏感操作向绑定手机号发送 SMS 通知 |

**异常场景处理：**

| 场景 | 处理方案 |
|------|----------|
| 忘记密码 | App 登录页"忘记密码"→ 输入手机号 → OTP 验证 → 设置新密码 → 所有设备重新登录 |
| 账号被盗 | 联系客服 → SA 后台强制踢出所有设备 → 重置密码 → 发送新临时密码到绑定手机号 |
| 手机号不能用（SIM卡丢失） | 联系客服线下验证身份 → SA 后台换绑新手机号 |
| 连续 5 次密码错误 | 锁定 15 分钟；锁定期间展示倒计时；不可使用 OTP 登录绕过 |
| 账号被禁用 | App 展示"账号已被停用"页面 + 联系管理员入口；5 分钟内当前会话自动登出 |

**验收标准：**
- [ ] 修改密码后所有设备立即登出
- [ ] 忘记密码流程：OTP 验证 → 设置新密码 → 重新登录
- [ ] 登录设备列表正确展示，支持远程登出单个设备
- [ ] 新设备登录向绑定手机号发送 SMS 通知
- [ ] 连续 5 次密码错误锁定 15 分钟，锁定期间 OTP 登录也禁用
- [ ] 账号被禁用后 App 展示明确提示

**门店关店——关联账号批量处理：**

```

  → 系统自动执行：
      1. 该门店所有 ROLE-CLK 和 ROLE-OWN 的 user_role_assignment → disabled
      2. 该门店所有平板设备 → 远程登出 + 锁定（展示"该门店已关闭"）
