## 模块概述
平板质检工具（TAB）是门店一体机（Android 定制平板）上的核心作业应用。店员通过该工具完成旧机回收的标准化质检流程：从用户身份验证开始，依次完成外观影像采集、硬件自动审计、发票信息采集，再将数据综合上传至云端；云端定价后，平板展示质检报告和抵扣报价供店员与用户当面确认；用户接受报价后进入核销流程，平板同步展示核销状态。
完整质检流程如下：

```
店员登录平板 → 用户OTP验证 → 加载预约信息（如有）
  → 外观影像采集（10张照片 + 1段视频）
    → 外观拒收判断
      ├── 外观无法回收 → 拒收流程（TAB-P0-08）
      └── 外观正常 → 外观AI自动检测（店员审核确认，TAB-P0-13）
                      → 硬件自动审计（USB连接）
                        → 发票信息采集（可选）
                          → 综合数据上传
                            → 质检报告展示（云端回传）
                              → 用户接受/拒绝报价
                                └── 接受 → 核销状态同步

```
**核心设计原则：**
- 流程不可跳步：每个步骤必须完成后才能进入下一步
- 数据本地优先：采集数据先存本地，上传成功后清理
- 断点续检：任意环节中断后可从上次完成点恢复
- 离线可用：网络中断时核心质检流程不中断
- 状态可追溯：每次操作的店员、时间、设备信息全程记录

## P0 核心功能
## TAB-P0-01 外观影像采集
**优先级：** P0
**功能描述：**
店员通过平板内置相机，对用户旧机进行标准化外观影像采集。采集过程由平板界面以图示叠加层（overlay）引导，按固定顺序完成正面屏幕、背面后盖、前、后、左、右、左上角、右上角、左下角、右下角共十个角度的拍照，以及一段不少于 10 秒的 360 度旋转视频。每个角度均提供参考图叠加层，帮助店员将设备放置到正确位置和角度。采集过程中支持对任意照片或视频单独重拍，不限次数。
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 采集引导 | 平板界面以图示叠加层（overlay）引导店员将设备放置到指定位置和角度；每个角度提供半透明参考线框和设备轮廓 |
| 拍照数量 | 固定 10 张照片，对应 10 个预设角度，缺一张不可提交 |
| 拍照顺序 | 必须按固定顺序完成：正面屏幕 → 背面后盖 → 前 → 后 → 左 → 右 → 左上角 → 右上角 → 左下角 → 右下角；每个角度拍摄完成后自动切换到下一个角度引导 |
| 视频时长 | 最短 10 秒，最长 30 秒，需完整覆盖设备 360 度旋转 |
| 分辨率要求 | 照片不低于 1080P（1920x1080），视频不低于 720P/30fps |
| 重拍机制 | 每张照片/视频可单独重拍，不限次数；重拍后覆盖原文件 |
| 本地缓存 | 采集的原始文件先存平板本地，上传成功后标记为可清理 |
| 存储格式 | 照片：JPEG（质量 ≥ 85%）；视频：MP4（H.264 编码） |
| 文件命名 | `{session_id}_{angle_id}_{timestamp}.jpg` / `.mp4` |
**输入：** 店员操作（对准设备、点击拍照、开始/停止录像）
**输出：** 10 张外观照片（JPEG，≥1080P）+ 1 段旋转视频（MP4，≥720P/30fps），暂存本地
**验收标准：**
- [ ] 平板界面按固定顺序引导 10 个角度拍照，每个角度有半透明参考叠加层
- [ ] 不可跳过任何角度；当前角度未完成拍摄时"下一步"按钮置灰
- [ ] 视频录制最短 10 秒，不足时提示"录制时间不足，请重新录制"，计时器红色闪烁
- [ ] 视频录制超过 30 秒自动停止
- [ ] 每张照片和视频支持单独重拍，重拍后即时预览替换后的影像
- [ ] 采集完成后可进入预览模式，左右滑动查看全部影像文件
- [ ] 照片分辨率检测：低于 1080P 时提示"照片分辨率不足，请调整相机设置"
- [ ] 拍摄界面显示已完成的进度（如"3/10 张照片"）

## TAB-P0-13 外观AI自动检测
**优先级：** P0
**功能描述：**
外观影像采集完成后，平板将 10 张外观照片和 360° 旋转视频上传至服务端 AI 检测服务。AI 根据预定义的 5 大维度 26 项缺陷判定规则，自动识别设备外观缺陷并返回结构化检测结果、置信度评分和推荐的成色等级。店员在平板上审核 AI 结果——高置信度项自动通过，低置信度或 AI 标记"疑似"的项高亮提示店员人工确认。仅在 AI 服务不可用（网络中断或 P0 早期 AI 模型未就绪）时降级为手动点检模式。

**产品愿景（目标态）：**
10 张照片 + 1 段视频 → AI 自动分析（< 5 秒）→ 返回完整点检结果 + 缺陷位置标注 → 店员审核确认（30 秒内完成）→ 提交。消除人工主观判断偏差，检测一致性 > 95%。

**实现路径：**

| 阶段 | 模式 | 说明 |
|------|------|------|
| **P0 MVP**（AI 未就绪） | 手动点检 | 店员对照判定标准逐项手动勾选（详见 §手动点检标准） |
| **P0 目标态**（AI 就绪） | AI 自动检测 + 人工审核 | AI 从影像自动识别缺陷并返回结果；店员审核确认/修正 |
| **P1 增强** | AI + 置信度分级 | 高置信（> 90%）自动填充不可修改；中置信（70-90%）可修改；低置信（< 70%）高亮强制人工判定 |

---

### AI 检测能力定义

AI 模型接收 10 张标准角度照片 + 1 段 360° 旋转视频，输出结构化检测结果。每个检测项返回：`{detected_grade, confidence, bbox, evidence_photo_index}`。

| 维度 | 项数 | AI 输入源 | AI 检测方法 | 可检测项 |
|------|:---:|------|------|------|
| 屏幕显示 | 6 | 正面上电图（第1张） | 图像分割 + 异常检测：纯白画面下识别色块/残影/坏点/漏液区域 | D1-D5 |
| 屏幕玻璃 | 4 | 正面熄屏图 + 侧面反光图（第1/3/7/8张） | 边缘检测 + 纹理分析：识别划痕线条、裂纹形态、反光面平整度 | G1-G4 |
| 机身边框 | 6 | 四角 + 侧面图（第3-10张） | 目标检测 + 轮廓比对：识别掉漆区域、凹陷、变形曲率、螺丝完整性 | B1-B6 |
| 后盖与机身 | 5 | 背面图 + 视频截图（第2张 + 视频关键帧） | 纹理分析 + 异常检测：识别划痕、碎裂纹理、鼓包轮廓、镜片划痕 | RC1-RC5 |
| 接口与按键 | 5 | 底部/侧面微距图（第5/6张） | 局部放大 + 颜色分析：检测接口金属触点颜色（腐蚀检测）、按键高度偏差 | P1-P5 |

**AI 置信度分级：**

| 置信度 | 含义 | 处理方式 |
|:---:|------|------|
| ≥ 90% | 高置信，AI 确定 | 自动填充结果，店员无需逐项确认（仅汇总展示） |
| 70-90% | 中置信，AI 判断 | 自动填充，但该项黄色高亮，店员需扫一眼确认 |
| < 70% | 低置信 / AI 不确定 | 标记"待人工判定"，红色高亮，店员必须手动选择 |
| N/A | AI 无法判断 | 如照片角度不理想、遮挡等 → 强制人工判定 |

### 店员审核流程（AI 模式）

```
外观影像采集完成 → 照片+视频上传至服务端
  → AI 检测服务分析（< 5 秒）
  → 返回结构化检测结果
  → 平板展示 AI 检测结果汇总

平板审核界面：
┌──────────────────────────────────────────────┐
│  AI 外观检测完成 · 整体置信度 87% · v1.2.0   │
├────────────────────┬─────────────────────────┤
│                    │  检测结果（5维度）       │
│  10张照片+视频     │                         │
│  (可点击放大)      │  ✅ 屏幕显示  5/6 通过   │

│  点击框→跳转对应项 │                         │
│                    │  ✅ 机身边框  5/6 通过   │
│                    │      · 1项待确认        │

```

**店员操作流程：**

1. **快速浏览**：查看 AI 检测结果汇总，5 个维度的通过/待确认概览
2. **聚焦待确认项**：点击"查看全部待确认项"，逐项审核 AI 标记的低置信或疑似缺陷项
   - 左侧照片自动定位到对应角度，AI 检测到的缺陷区域用红框标注
   - 右侧展示 AI 判断结果 + 置信度 + 判定标准参考
   - 店员可选择：确认 AI 结果 / 修正为其他等级 / 标记"AI 误判（正常）"
3. **抽查高置信项**：可展开任何已通过维度，查看 AI 判断的缺陷项照片标注，手动抽查
4. **手动模式切换**：若店员认为 AI 整体结果不可信（罕见），可"切换到手动"进入逐项点检
5. **确认提交**：所有待确认项处理完毕 → 点击"确认全部"→ 结果上传

**UI 交互规则：**

| 规则项 | 说明 |
|--------|------|
| 照片联动 | 点击检测项 → 左侧自动切换到 AI 标注了缺陷框的证据照片，缺陷区域高亮闪烁 |
| 置信度可视化 | 高置信（绿）→ 自动通过无需确认；中置信（黄）→ 需扫一眼确认；低置信（红）→ 必须手动判定 |
| 缺陷位置标注 | AI 在照片上画出缺陷边界框 + 标签（如"浅划痕 92%"）→ 店员可点击框查看详情或删除误检框 |
| 修正操作 | 店员可修改 AI 判断等级、删除 AI 误检框、手动新增 AI 遗漏的缺陷框 |
| 切换手动 | 一键切换到手动静默模式（保留 AI 结果作为参考，但允许逐项自由修改） |
| AI 模型版本 | 审核界面展示当前 AI 模型版本号，用于问题追溯和模型迭代对比 |

**业务规则：**

| 规则项 | 说明 |
|--------|------|
| AI 优先，人工兜底 | 服务端 AI 可用时默认走 AI 模式；AI 不可用（超时/模型未部署）时自动降级为手动模式 |
| 高置信自动通过 | 置信度 ≥ 90% 且非拒收等级 → 自动填充，店员无需逐项操作，汇总页展示通过数量 |
| 拒收规则不受 AI 置信度豁免 | 即使 AI 高置信判断为"粉碎性碎裂"，仍需店员二次确认后才能触发拒收流程 |
| 人工修正记录 | 店员对 AI 结果的任何修改均记录：原 AI 判断、人工修正值、操作时间、店员 ID——用于模型迭代训练 |
| 手动模式数据保留 | 手动模式下完成的点检，AI 仍会后台运行并记录结果（与人工结果对比，用于模型评估，不影响定价） |
| 结果持久化 | AI 结果 + 店员修正均实时保存本地检查点 |

**验收标准：**
- [ ] AI 服务可用时，照片上传后 5 秒内返回检测结果
- [ ] AI 检测结果含 26 个检测项的等级、置信度、证据照片索引和缺陷边界框
- [ ] 高置信项（≥ 90%）自动通过，中置信项黄色高亮，低置信项红色标记待人工判定
- [ ] 点击待确认项时，左侧照片自动定位并标注 AI 检测到的缺陷区域
- [ ] 店员可修正 AI 等级、删除误检框、新增遗漏缺陷
- [ ] 所有人工修正记录原 AI 判断 + 修正值，上传至服务端用于模型迭代
- [ ] AI 不可用时自动降级手动模式，降级过程对店员透明（仅提示"AI 暂不可用"）
- [ ] 切换手动模式不丢失 AI 结果，手动模式下 AI 后台静默运行用于对比
- [ ] 所有待确认项处理完毕后才能提交

### 附录：手动点检标准（P0 MVP，AI 未就绪时使用）

> 以下为 AI 检测的判定规则基准，同时也是手动模式的店员参考标准。AI 模型的标注训练数据以此规则为准。

**维度一：屏幕显示缺陷（D1-D6）** — 检测方法：点亮屏幕显示全白画面，检查显示面板缺陷

| 编号 | 点检项 | 等级 | 判定标准 | 扣款代码 |
|------|--------|------|----------|----------|
| D1 | 显示老化/烧屏 | 无 → 轻微（仅纯色背景可见残影）→ 明显（大面积黄斑/图标烙印） | CO-SCR-04 |
| D2 | 亮点/坏点 | 无 → 1-2个(直径<0.5mm) → ≥3个或有彩线 | CO-SCR-05 |
| D3 | 屏幕变色/偏色 | 无 → 轻微局部偏色 → 大面积明显偏色 | CO-SCR-04/06 |
| D4 | 显示闪烁 | 无 → 偶尔 → 频繁/持续闪烁 | CO-SCR-06 |
| D5 | 液晶漏液/漏光 | 无 → 边缘漏光 → 漏液（黑色/紫色斑块） | CO-SCR-04/06 |
| D6 | 触摸功能 | 正常 → 局部不灵敏 → 大面积失灵（>30%）→ 触发拒收 | CO-SCR-06 |

**维度二：屏幕玻璃缺陷（G1-G4）** — 检测方法：熄屏，45° 角，30cm 距离观察

## TAB-P0-02 硬件自动审计
**优先级：** P0
**功能描述：**
店员通过 USB OTG 数据线将用户旧机连接至平板，平板自动运行硬件检测程序，读取设备核心硬件指标。检测过程无需人工干预，进度在平板界面实时展示。检测覆盖 9 大核心硬件项：IMEI/序列号、品牌型号、电池健康度、屏幕触控、传感器组、存储容量、摄像头、扬声器与麦克风、物理按键。检测顺序为先读取静态信息（IMEI/型号/存储），再执行交互式测试（触控/按键/音视频）。
当某项检测失败时，系统提供容错策略：自动重试（最多 2 次）、检测超时自动跳过标记、单项标记"异常"后允许手动录入（如手动输入 IMEI），或标记为"无法检测"并进入后续流程。单次检测超时阈值为 30 秒。
**检测项目详情：**

| 检测项 | 读取方式 | 输出值 | 失败处理 |
|--------|----------|--------|----------|
| IMEI / 序列号 | 系统 API 读取 | 1-2 个 IMEI（单/双卡） | 自动重试 2 次 → 手动录入 |
| 品牌 & 型号 | 系统 API 读取 | 品牌名 + 型号代码 | 自动重试 2 次 → 手动录入 |
| 电池健康度 | iOS: 系统电池健康 API；Android: ADB dumpsys batterystats | 百分比（0-100%） | 标记"无法检测" |
| 屏幕触控 | 触控点测试（多点触摸区域扫描） | 正常/异常区域坐标 | 标记"触控异常" + 异常坐标 |
| 传感器 | 加速度计/陀螺仪/距离传感器/光线传感器状态检测 | 各传感器 正常/异常 | 逐传感器标记异常项 |
| 存储容量 | 系统 API 读取总容量和可用容量 | 总容量 GB + 可用 GB | 标记"无法检测" |
| 摄像头 | 前后摄拍照测试，检测成像是否正常 | 正常/异常 | 标记"摄像头异常（前置/后置）" |
| 扬声器 & 麦克风 | 播放测试音 + 录音回采 | 正常/异常 | 标记"扬声器异常"/"麦克风异常" |
| 按键 | 音量键/电源键按压事件检测 | 正常/异常 | 标记"按键异常（音量+/音量-/电源）" |
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 连接方式 | USB OTG 数据线连接；平板自动检测设备接入 |
| 启动方式 | USB 连接后 5 秒内自动开始检测，无需手动触发 |
| 检测顺序 | 先读取静态信息（IMEI/型号/存储），再执行交互式测试（触控/按键/音视频） |
| 超时处理 | 单项检测超过 30 秒无响应，标记为"检测超时"并自动重试 1 次；仍超时则跳过，继续下一项 |
| 失败重试 | 单项检测失败后自动重试最多 2 次（含首次共 3 次尝试） |
| 不可跳过 | 所有检测项必须执行，不支持人为勾选跳过；超时/失败项自动标记后继续 |
| 异常标记 | 检测正常以绿色高亮，异常以红色高亮，超时/跳过以黄色高亮 |
| 复测 | 支持对单项进行复测，不影响已完成的检测结果；复测结果覆盖原结果 |
| 检测完整性 | 所有 9 项均有结果（正常/异常/超时/手动录入）才算检测完成 |
| 手动录入 | IMEI 和品牌型号项失败后支持手动输入；输入后标记为"手动录入"并以蓝色高亮 |
| 设备兼容 | Android 设备走 ADB 检测；iOS 设备走 libimobiledevice 检测 |
**输入：** USB OTG 连接设备
**输出：** 硬件检测结果报告（结构化 JSON，含各项正常/异常/超时状态、具体数值、异常详情）
**验收标准：**
- [ ] USB 连接后 5 秒内自动开始检测，平板界面显示"正在检测设备..."
- [ ] 所有 9 项检测逐一执行，进度条实时更新，显示当前检测项名称
- [ ] 正常项绿色高亮，异常项红色高亮，超时项黄色高亮，手动录入项蓝色高亮
- [ ] 单项超时 30 秒后自动重试 1 次，仍超时则跳过并标记黄色
- [ ] 单项检测失败后自动重试最多 2 次
- [ ] IMEI/品牌型号检测失败后弹出手动输入框，录入格式校验（IMEI 15 位数字）
- [ ] 支持单项复测，复测结果覆盖原结果并更新状态颜色
- [ ] 检测完成后平板界面展示完整结果汇总，异常项数量统计
- [ ] USB 意外断开时保存已完成结果，提示"设备已断开，请重新连接"
- [ ] 检测结果 JSON 包含每项的详细数据：状态、数值、时间戳、重试次数

## TAB-P0-03 综合数据上传
**优先级：** P0
**功能描述：**
外观影像文件与硬件检测结果，以及可选的发票信息，打包后统一上传至云端中台。上传过程显示进度（百分比 + 剩余文件数），支持断点续传。上传成功后自动触发绑定——将质检数据与当前换购会话关联，云端生成唯一 `session_id` 回传至平板。
**上传数据包结构：**

| 数据分类 | 内容 | 格式 |
|----------|------|------|
| 外观影像 | 10 张外观照片 + 1 段旋转视频 | JPEG + MP4 |
| 硬件检测 | 9 项检测结果 + 各项详细数据 | JSON |
| 发票信息 | 发票照片 + 金额 + 购买日期（可选） | JPEG + JSON |
| 上下文信息 | 平板设备 ID + 门店 ID + 操作店员 ID + 时间戳 | JSON |
| 会话信息 | OTP 验证后的 session 关联标识 | JSON |
| 完整性校验 | 数据包 hash（SHA-256） | string |
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 上传内容 | 10 张照片 + 1 段视频 + 硬件检测 JSON 结构体 + 平板设备 ID + 门店 ID + 操作店员 ID + 时间戳 + 发票信息（如有） |
| 上传顺序 | 先传影像文件（大文件，分片上传），后传硬件 JSON（小体积），全部完成后云端统一校验 |
| 断点续传 | 网络中断后恢复时，从已上传的断点继续，不重传已完成的分片；每分片上传成功后本地记录分片状态 |
| 分片大小 | 每分片 2MB；单个文件最大支持 100MB |
| 自动绑定 | 云端收到完整数据后，自动创建换购会话，生成唯一的 `session_id`，回传至平板 |
| 上传超时 | 单次上传总时长超过 5 分钟仍未完成，提示"网络不稳定，可稍后重试"，保留本地数据 |
| 重复上传防护 | 同一批数据（以影像文件 hash + 硬件数据 hash 联合作为幂等键）不可重复提交；云端返回 409 Conflict |
| 上传失败 | 失败时本地数据完整保留，支持手动重试；重试按钮在失败提示上直接显示 |
| 并发控制 | 同一平板同时只允许一个上传任务进行 |
**输入：** 外观影像文件 + 硬件检测结果 + 门店/店员上下文 + 发票信息（可选）
**输出：** 上传状态（成功/失败/进行中）+ `session_id` + 云端校验结果
**验收标准：**
- [ ] 上传进度条实时更新，显示百分比和"剩余 N 个文件"
- [ ] 网络中断后恢复，上传从中断点继续而非重新开始
- [ ] 上传成功后平板 3 秒内收到 `session_id`
- [ ] 同一批数据重复提交时云端拒绝并返回"数据已存在"（409），平板提示"该数据已上传"
- [ ] 上传失败时本地数据保留，界面展示"重试"按钮
- [ ] 上传超时 5 分钟后自动中止，提示"网络不稳定，可稍后重试"
- [ ] 分片上传过程中每个分片完成有视觉反馈（进度微调）
- [ ] 上传完成后本地标记原始文件为"可清理"状态

## TAB-P0-05 核销状态同步
**优先级：** P0
**功能描述：**
用户接受报价后，核销流程转移至店老板 App 和用户 App 完成，平板不再承担核销操作职能。平板在此期间展示核销流程的实时状态，供店员了解当前进度。核销状态随店老板和用户的操作实时更新，店员可清晰知道何时将旧机交付给 DB（配送员）。
**平板展示的核销状态流转：**

| 状态 | 触发条件 | 平板展示内容 | 店员操作指引 |
|------|----------|-------------|-------------|
| 待核销 | 用户已接受报价 | 展示旧机抵扣金额 + 提示"核销流程已推送至店老板 App，请等待店老板确认" | 告知用户等待，无需操作 |
| 核销中 | 店老板已录入售价 | 展示"店老板已录入售价，等待用户在新手机确认" + 新机信息摘要（机型/售价/差价） | 可协助用户查看新机信息 |
| 已核销 | 用户在 App 确认 | 展示"核销成功"（绿色对勾动画）+ 旧机信息摘要 + 提示"请将旧机交给 DB（配送员）" | 店员将旧机当面交给 DB |
| 核销失败 | 用户拒绝或超时 | 展示"核销未完成" + 失败原因 + "联系店老板处理"入口 | 引导用户联系店老板 |
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 状态同步方式 | WebSocket 长连接实时推送，心跳间隔 30 秒 |
| 同步延迟 | 目标 ≤ 3 秒（从店老板/用户操作到平板展示） |
| 超时处理 | 核销 30 分钟后未完成，平板展示"核销超时，请联系店老板" |
| 断连恢复 | WebSocket 断开后自动重连，重连后拉取最新状态 |
| 操作权限 | 平板仅查看核销状态，不可执行核销操作（录入金额/确认等在店老板 App 和用户 App 完成） |
| 状态历史 | 平板展示核销状态流转时间线（每个状态 + 时间戳） |
**输入：** 云端推送的核销状态变更事件
**输出：** 平板核销状态页面 + 店员操作指引
**验收标准：**
- [ ] 用户接受报价后平板同步展示核销状态，无需手动刷新
- [ ] 核销状态随店老板和用户操作实时更新（延迟 ≤ 3 秒）

## TAB-P0-07 到店用户 OTP 验证与注册
**优先级：** P0
**功能描述：**
所有到店用户（无论是否预约）统一通过手机号 + OTP 验证身份。店员在平板输入用户手机号，系统发送一条 SMS（含 6 位 OTP + H5 跟踪短链）。用户告知店员 OTP（或出示手机屏幕），店员在平板输入 6 位 OTP 完成验证。验证通过后系统自动匹配预约信息（如有）、关联已有账号或创建新账号、建立到店会话，随即进入质检流程。用户点击 SMS 中的短链可在 H5 页面（或 App）查看质检报告和接受报价。
**操作流程：**

```
店员在平板输入用户手机号
  → 系统校验手机号格式（10 位印度手机号）
  → 系统发送 SMS：OTP + H5 跟踪链接
  → 用户告知店员 OTP（或出示手机屏幕）
  → 店员在平板输入 6 位 OTP
  → 系统验证 OTP：
      ├── 验证通过 → 身份确认
      │     → 有预约？→ 自动加载预约信息（平板展示旧机自填+初步估价）
      │     → 有账号？→ 关联已有账号
      │     → 无账号？→ 自动创建新账号（手机号为标识，标记来源"线下注册"）
      │     → 创建到店会话 session_id
      │     → 平板展示会话详情（用户信息摘要 + 预约信息）
      │     → 进入质检环节
      └── 验证失败 → 提示"OTP 错误，剩余重试 X 次"
            → 超过 3 次 → 60 秒冷却，冷却期间按钮置灰+倒计时
            → 可重发 OTP（冷却结束后或用户请求重发）

```
**OTP 设计：**

| 设计点 | 说明 |
|--------|------|
| OTP 长度 | 6 位数字 |
| 有效期 | 60 秒，过期需重新发送；平板展示剩余有效秒数倒计时 |
| 发送渠道 | SMS（优先），WhatsApp Business API（备选，SMS 发送失败时自动切换） |
| 重试次数 | 最多 3 次错误输入；超过后 60 秒冷却，冷却期间 OTP 输入框禁用 |
| 每日上限 | 同一手机号每天最多发送 5 次 OTP；超限提示"今日验证次数已达上限，请明日再试" |
| 频率限制 | 同一手机号两次发送 OTP 间隔 ≥ 30 秒 |
**SMS 模板：**

```
[Platform] OTP: 123456
Track: bott.in/s/abc123
Valid 60s. Do not share.
आपका OTP: 123456

```
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 统一入口 | 所有用户到店统一走手机号 + OTP，不再区分预约/到店 |
| 手机号校验 | 印度手机号格式：10 位数字，以 6/7/8/9 开头 |
| 账号匹配 | 手机号已注册 → 关联已有账号，加载用户历史记录；未注册 → 自动创建账号，标记来源为"线下注册" |
| 预约匹配 | OTP 验证通过后自动查预约表，有预约则加载旧机自填信息和初步估价供店员参考 |
| H5 链接 | SMS 中的短链指向 H5 会话跟踪页，随质检进度自动更新内容（质检中/报告/报价/核销完成） |
| 已有 App 用户 | 已安装 App 的用户可在 App 内查看报告和接受报价，SMS 短链作为备用入口 |
| 无 SIM 用户 | 极端情况（旧机是用户唯一设备且已关机），走 P2 阶段的店员担保验证通道 |
| 会话生命周期 | 自创建起 2 小时内有效；超时未完成质检则会话自动过期，需重新 OTP 验证 |
**输入：** 店员输入用户手机号 + OTP
**输出：** 验证结果 + 用户身份信息 + 预约信息（如有）+ session_id
**验收标准：**
- [ ] 输入手机号后 3 秒内系统发送 SMS（含 OTP + H5 短链）
- [ ] 手机号格式校验：非 10 位数字或不合法前缀时提示"请输入有效的手机号码"
- [ ] OTP 正确输入后 2 秒内验证通过，自动创建会话
- [ ] 有预约时加载预约信息展示在平板上（旧机自填 + 初步估价）
- [ ] 无预约时创建空白新会话，直接进入质检
- [ ] OTP 错误时提示"OTP 错误，剩余重试 X 次"，3 次后冷却 60 秒
- [ ] 冷却期间展示倒计时（秒），输入框和确认按钮禁用
- [ ] OTP 60 秒过期后提示"OTP 已过期，请重新发送"，自动显示"重新发送"按钮
- [ ] 用户点击 SMS 短链打开 H5 页面，随进度更新（质检中/报告/报价/核销完成）
- [ ] 每日 5 次上限后提示"今日验证次数已达上限，请明日再试"
- [ ] SMS 发送失败时自动切换 WhatsApp 发送，失败切换对店员透明

## TAB-P0-08 外观拒收
**优先级：** P0
**功能描述：**
外观影像采集完成后，店员根据外观检查结果判断设备是否可回收。若外观明显不可回收（如屏幕粉碎性碎裂、机身严重弯曲变形、主板裸露、进水腐蚀严重等），店员可在平板点击"拒收该设备"，拍摄损坏细节照片并选择拒收原因，完成拒收操作。拒收后会话终止，不进入硬件检测和定价环节，不创建 IMEI 库存记录。
**操作流程：**

```
外观影像采集完成 → 店员目视判断
  ├── 外观正常 → 点击"继续检测"（正常流程）
  └── 外观无法回收 → 点击"拒收该设备"
        → 拍摄损坏细节照片（最少 3 张，最多 10 张；含正面全景、背面全景、至少 1 张损坏细节特写）
        → 从预设列表单选拒收原因
        → （如选择"其他异常情况"）填写补充说明（必填，最少 10 字）
        → 点击"确认拒收" → 二次确认弹窗："确认拒收该设备？拒收后不可撤销"
        → 确认后上传至云端
        → 会话标记 [已完成-拒收]
        → 店员告知用户拒收原因，当面归还设备

```
**拒收原因预设列表（店员单选，不可自由输入）：**

| 拒收原因 | 说明 | 引导拍摄要点 |
|----------|------|-------------|
| 屏幕严重碎裂 | 屏幕玻璃粉碎，显示层暴露或漏液 | 特写碎裂区域，反光角度拍摄 |
| 机身严重弯曲变形 | 机身明显弯曲，无法平放或外壳分离 | 侧拍弯曲角度，平放桌面俯拍间隙 |
| 进水腐蚀严重 | 主板或内部有明显水渍、腐蚀痕迹 | 特写腐蚀区域和防水标（如有） |
| 主板损坏/缺失 | 主板裸露、烧毁或已被拆除 | 拍摄主板全貌 |
| 配件缺失过多 | 缺少屏幕、电池等核心组件 | 拍摄缺失组件部位 |
| 用户主动放弃回收 | 用户在质检过程中改变主意 | 无需特写，拍摄设备当前状态即可 |
| 其他异常情况 | 需补充说明文字 | 拍摄异常部位特写 |
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 操作入口 | 外观影像采集完成后，平板展示两个操作按钮："继续检测"（主按钮，绿色）和"拒收该设备"（次要按钮，红色/灰色） |
| 照片数量 | 最少 3 张，最多 10 张；必须包含正面全景、背面全景、至少 1 张损坏细节特写 |
| 拒收原因 | 单选预设项；"其他异常情况"需额外填写文字说明（必填，最少 10 字，最多 200 字） |
| 不可撤销 | 确认拒收后不可撤回，该设备无法更改状态重新进入质检 |
| 二次确认 | 点击"确认拒收"后弹出确认弹窗，明确告知"拒收后不可撤销" |
| 会话状态 | 标记为 [已完成-拒收]，与正常完成换购的 [已完成] 区分 |
| 不计入库存 | 拒收设备不创建 IMEI 库存记录 |
| 数据用途 | 拒收记录用于分析门店拒收率、常见拒收原因分布，优化预约环节用户自填引导 |
| 拒收时间限制 | 仅在外观采集完成到硬件检测开始之间可拒收；一旦开始硬件检测，不可再拒收 |
**输入：** 店员拍摄的损坏照片 + 选择的拒收原因 + 补充说明（如适用）
**输出：** 拒收记录（照片、原因、店员 ID、门店 ID、时间戳）+ 会话状态变更
**验收标准：**
- [ ] 外观采集完成后平板展示"继续检测"（绿色）和"拒收该设备"（红色文字/灰色底）两个操作入口
- [ ] 拒收时强制拍照 ≥ 3 张，不满足时"确认拒收"按钮置灰并提示"请至少拍摄 3 张损坏照片"
- [ ] 照片达到 10 张上限后拍照按钮置灰，提示"已达照片上限（10 张）"
- [ ] 拒收原因从预设列表单选，选择"其他异常情况"时弹出文字输入框
- [ ] "其他"文字说明不足 10 字时提示"请补充至少 10 字说明"，提交按钮置灰
- [ ] 点击"确认拒收"后弹窗二次确认"确认拒收该设备？拒收后不可撤销"
- [ ] 确认拒收后不可撤销，会话状态变更为 [已完成-拒收]
- [ ] 拒收记录包含照片（3-10 张）、原因、补充说明（如有）、店员 ID、门店 ID、时间戳
- [ ] 拒收后不创建 IMEI 库存，不进入定价
- [ ] 开始硬件检测后拒收入口不可见

## TAB-P0-09 发票信息采集
**优先级：** P0
**功能描述：**
硬件审计完成后、数据上传前，店员可询问用户是否携带了设备购买发票。若用户提供发票，店员在平板拍摄发票照片并录入发票金额和购买日期。发票信息为可选操作——不提供发票不影响质检流程和定价。发票数据随质检数据一同上传，定价引擎若检测到发票则以 `min(发票价格, 市场基准价)` 作为基准价。
**操作流程：**

```
硬件审计完成
  → 平板提示"用户是否提供购买发票？"
      ├── 提供 → 进入发票采集界面
      │         → 拍摄发票照片（需包含金额和日期区域，提供取景框引导）
      │         → 录入发票金额 (INR) + 购买日期（日期选择器）
      │         → 点击"确认" → 预览确认 → 进入综合上传
      └── 跳过 → 直接进入综合上传

```
**录入字段：**

| 字段 | 录入方式 | 是否必填 | 校验规则 |
|------|----------|----------|----------|
| 发票照片 | 平板拍照 | 必填（如录入发票） | 需清晰可辨金额和日期；照片分辨率 ≥ 1080P |
| 发票金额 | 手动输入数字 | 必填（如录入发票） | INR，正整数，范围 1-999,999；以发票上标注的最终成交价为准 |
| 购买日期 | 日期选择器 | 必填（如录入发票） | 不可晚于今天，不可早于设备出厂日期；用于判断设备使用时长 |
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 可选操作 | 不提供发票不影响质检流程，店员可跳过 |
| 不可后补 | 综合上传完成后不可再补录发票（需在质检环节完成） |
| 不做真伪校验 | MVP 阶段仅采集发票信息，不接入 GST 发票验证系统 |
| 仅拍照存档 | 发票照片与外观影像一同存储，供运营审核时参考 |
| 定价影响 | 发票金额用于定价引擎计算基准价：`min(发票价格, 市场基准价)` |
| 上传前确认 | 发票录入完成后展示预览确认页，支持重新拍照或修改金额/日期；确认后不可返回修改 |
**输入：** 店员拍摄发票照片 + 录入金额和日期
**输出：** 发票信息（照片 + 金额 + 日期），随质检数据一同上传
**验收标准：**
- [ ] 硬件审计完成后平板弹出"是否提供发票"选项（两个按钮："提供发票"/"跳过"）
- [ ] 选择"提供"后进入发票采集界面：取景框引导拍摄发票全貌
- [ ] 金额输入框仅接受正整数，自动格式化（如 50000 → "₹50,000"）
- [ ] 购买日期选择器不可选未来日期
- [ ] 选择"跳过"后直接进入上传流程，不阻塞
- [ ] 发票信息（照片 + 金额 + 日期）随质检数据一同上传
- [ ] 发票录入完成后展示预览确认页，支持重新拍照或修改
- [ ] 综合上传完成后不可再补录发票

## TAB-P0-10 OTA 远程更新
**优先级：** P0
**功能描述：**
质检 App 及其内置资源（相机引导叠加层、硬件检测脚本、拒收原因列表等）支持远程 OTA 更新。当云端发布新版本后，平板在空闲时段（或下次启动时）检测更新、下载更新包、校验完整性后安装更新。更新失败时自动回滚至上一个可用版本。OTA 更新机制覆盖：App 本体更新、内置检测脚本更新、相机引导资源更新、UI 文案和配置更新。
**更新类型与策略：**

| 更新类型 | 内容 | 更新策略 | 是否需要重启 |
|----------|------|----------|-------------|
| App 本体更新 | APK 安装包 | WiFi 环境下自动下载，下载完成后弹窗提示安装 | 是（安装新 APK） |
| 检测脚本更新 | 硬件检测逻辑/参数 | 静默下载，即时生效 | 否（热加载） |
| 引导资源更新 | 相机叠加层图片/角度配置 | 静默下载，即时生效 | 否（资源刷新） |
| 配置更新 | 拒收原因列表/文案/业务参数 | 静默下载，即时生效 | 否（配置刷新） |
**更新流程：**

```
云端发布新版本
  → 平板定时轮询（每 30 分钟）或 App 启动时检查更新
  → 检测到新版本
      → 检查当前平板状态：
          ├── 质检进行中 → 延迟至质检完成后下载
          └── 空闲状态 → 开始下载
  → 下载更新包（后台静默，通知栏展示进度）
  → 下载完成 → SHA-256 完整性校验
      ├── 校验通过 → 根据更新类型执行安装/热加载
      │     ├── App 本体 → 弹窗"新版本已就绪，是否立即安装？"
      │     │     ├── 立即安装 → 关闭 App → 安装 APK → 启动
      │     │     └── 稍后 → 下次 App 启动时自动安装
      │     └── 资源/脚本/配置 → 静默替换，记录版本号
      └── 校验失败 → 删除下载包 → 提示"更新包校验失败，将自动重试" → 重新下载（最多 3 次）
  → 安装后校验：
      ├── 安装成功 → 更新本地版本号 → 记录更新日志
      └── 安装失败 → 自动回滚至上一版本 → 上报失败日志至云端

```
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 更新检查频率 | 每 30 分钟轮询一次 + App 启动时立即检查 |
| 下载条件 | App 本体更新：仅 WiFi 环境下载（可配置）；资源/脚本更新：WiFi 或移动网络均可 |
| 下载中断恢复 | 支持断点续传；网络恢复后从断点继续下载 |
| 完整性校验 | SHA-256 hash 校验；校验失败自动重新下载（最多 3 次） |
| 质检中不打扰 | 质检流程进行中时，不弹更新提示；更新包后台下载但不安装，待质检完成后提示 |
| 回滚机制 | 安装失败自动回滚至上一个可用版本；回滚后 App 仍可正常使用 |
| 强制更新 | 支持云端标记"强制更新"；强制更新版本在 App 启动时阻断使用，必须更新后才能进入 |
| 版本记录 | 平板本地记录所有更新历史（版本号、更新时间、更新类型、结果） |
| 灰度发布 | 支持按门店/地区灰度推送更新 |
| 资源版本管理 | 每个资源类别独立版本号，如 `camera_guide_v3`、`test_script_v2.1` |
**输入：** 云端发布的更新包（APK / 资源包 / 配置包）
**输出：** 平板更新状态（已更新/更新失败/待更新）+ 更新日志
**验收标准：**
- [ ] App 启动时自动检查更新，有更新时通知栏展示"发现新版本"
- [ ] 资源/配置更新静默下载并即时生效，无需用户感知
- [ ] App 本体更新仅在 WiFi 环境下下载（移动网络下仅提示）
- [ ] 下载中断后恢复时支持断点续传
- [ ] 更新包下载完成后 SHA-256 校验，校验失败自动重试最多 3 次
- [ ] App 本体更新弹窗提供"立即安装"和"稍后"两个选项
- [ ] 安装失败自动回滚至上一版本，App 仍可正常打开使用
- [ ] 强制更新版本启动时阻断使用，展示"请更新至最新版本"界面
- [ ] 质检进行中不弹更新提示，完成后自动提示
- [ ] 更新历史可追溯（设置 → 关于 → 更新日志）

## TAB-P0-11 质检中断恢复
**优先级：** P0
**功能描述：**
质检流程的每一步骤完成后，系统自动将当前进度和已完成数据持久化保存至本地。当发生 App 崩溃、平板意外断电、USB 连接断开等异常中断后，重新进入 App 时可从上次中断的检查点恢复，继续未完成的步骤，避免重复操作。恢复机制覆盖所有质检步骤：外观采集、硬件检测、发票采集、数据上传。
**状态保存检查点：**

| 质检步骤 | 检查点触发时机 | 保存内容 |
|----------|--------------|----------|
| OTP 验证 | OTP 验证通过后 | session_id、用户手机号、验证时间 |
| 外观采集 | 每张照片拍摄完成后 | 已拍照片列表（含文件路径和角度 ID）、视频文件路径、当前进度 |
| 外观拒收 | 拒收确认提交后 | 拒收照片、拒收原因、补充说明、会话状态 |
| 硬件检测 | 每项检测完成后 | 已完成检测项结果 JSON、当前检测进度、USB 连接状态 |
| 发票采集 | 发票信息确认后 | 发票照片路径、金额、日期 |
| 综合上传 | 每分片上传成功后 | 已上传分片列表、上传进度、云端 session_id |
**恢复流程：**

```
App 重新启动 / 异常恢复
  → 检测本地是否有未完成的会话（查询本地持久化状态表）
      ├── 无未完成会话 → 正常进入首页
      └── 有未完成会话 → 弹出恢复提示：
            "检测到未完成的质检会话 [设备型号] [中断时间]
             是否从上次中断处继续？"
            ├── 继续 → 加载本地数据 → 恢复到中断时的步骤
            │     → 已完成的步骤标注"已完成"，可直接跳过
            │     → 从中断的检查点开始继续操作
            └── 放弃 → 清除本地会话数据 → 开始新会话

```
**中断场景与恢复策略：**

| 中断场景 | 恢复策略 | 数据保护 |
|----------|----------|----------|
| App 崩溃（闪退） | 重启后自动检测未完成会话，恢复至崩溃前检查点 | 步骤完成时已持久化，未保存的当前步骤数据可能丢失 |
| 平板意外断电 | 重新开机后 App 启动，检测未完成会话并恢复 | 依赖本地持久化的检查点数据恢复 |
| USB 断开（硬件检测中） | 保存已完成检测项结果；提示"设备已断开"；重连后继续未完成项 | 已完成检测项不丢失；USB 重连后检测进度保持 |
| 网络中断（上传中） | 已上传分片不丢失；恢复网络后从断点续传 | 分片上传状态持久化至本地 |
| 用户主动退出 App | 保存当前进度；下次打开时恢复 | 同检查点机制 |
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 检查点保存 | 每个步骤完成后自动触发本地持久化（SQLite + 文件系统） |
| 保存频率 | 外观影像：每张照片拍摄后即时保存；硬件检测：每项检测完成后即时保存；上传：每分片上传成功后即时保存分片状态 |
| 恢复提示 | 有未完成会话时，App 启动后弹出恢复提示弹窗，不可跳过 |
| 会话过期 | 未完成会话超过 24 小时自动标记为"已过期"，清除本地数据 |
| 多会话处理 | 同时只允许一个活跃会话；新会话创建时需先完成或放弃旧会话 |
| 数据加密 | 本地持久化的会话数据使用 AES-256 加密存储 |
| 自动重试 | USB 断开后每 5 秒检测重连，重连后自动继续检测 |
| 手动跳过 | 硬件检测中某项超时/失败后支持手动跳过（标记黄色），不影响恢复流程 |
**输入：** App 启动事件 / 异常恢复触发
**输出：** 恢复至中断检查点的质检会话
**验收标准：**
- [ ] 每步骤完成后自动保存检查点数据至本地（SQLite + 文件系统）
- [ ] App 崩溃重启后自动检测未完成会话，弹出恢复提示弹窗
- [ ] 恢复后可从中断的检查点继续，已完成步骤标注"已完成"不可重新操作
- [ ] 外观采集恢复后已拍照片和视频完整保留
- [ ] 硬件检测恢复后已完成检测项结果保留，从下一项继续
- [ ] USB 断连重连后自动继续检测，无需手动触发
- [ ] 上传中断恢复后从已上传分片继续，不重传已完成分片
- [ ] 未完成会话超过 24 小时自动过期并清理本地数据
- [ ] 恢复提示弹窗提供"继续"和"放弃"两个选项
- [ ] 本地持久化数据使用 AES-256 加密，不可直接读取

## TAB-P0-12 平板注册登录与店员身份
**优先级：** P0
**功能描述：**
平板首次使用需完成设备注册，绑定至指定门店。店员通过手机号 + OTP（或密码）登录 App，系统校验店员身份及其与门店的绑定关系。同一平板支持多名店员共用，各店员的质检会话相互隔离。店员离职或换班时，管理员可远程回收其登录权限，被回收权限的店员无法继续使用平板。
**平板注册流程：**

```
平板首次开机 → 启动质检 App
  → 进入设备注册页
  → 展示平板设备 ID（自动读取） + 注册二维码
  → 门店管理员在后台管理系统扫描二维码 → 绑定平板与门店
  → 平板收到绑定确认 → 展示"绑定成功" + 门店名称 + 门店地址
  → 进入店员登录页

```
**店员登录流程：**

```
店员在登录页输入手机号
  → 系统校验手机号是否在本门店店员名单中
      ├── 在校验名单中 → 发送 OTP 或输入密码
      │     → 验证通过 → 进入工作台
      │     └── 验证失败 → 提示错误 + 剩余重试次数
      └── 不在名单中 → 提示"无权限，请联系管理员添加"

```
**店员身份管理：**

| 角色 | 权限范围 | 说明 |
|------|----------|------|

| 临时店员 | 质检全流程（无历史查看） | 临时顶班，权限在指定时间段有效 |
**会话隔离设计：**

| 隔离维度 | 实现方式 |
|----------|----------|
| 登录态 | 每个店员独立登录；切换店员需退出登录后重新登录 |

**权限回收与登出：**

| 场景 | 处理方式 |
|------|----------|
| 店员主动退出 | 清除本地登录态；进行中会话保留（下次登录恢复） |

**业务规则：**

| 规则项 | 说明 |

## TAB-P1-01 离线质检缓存
**优先级：** P1
**功能描述：**
当平板网络中断时，外观影像采集和硬件审计流程不中断，数据暂存本地。网络恢复后自动触发上传队列，按时间顺序依次补传。离线状态下已完成的质检数据以"待上传"标记管理。本地缓存使用 AES-256 加密存储，上传成功后即时删除。离线队列有容量上限。
**离线模式完整流程：**

```
网络中断（平板检测到无可用网络连接）
  → 平板顶部持续展示"离线模式"横幅（黄色/橙色）
  → 正在进行的质检流程不中断，继续执行
  → 每步完成的数据打上"待上传"标记 + 时间戳
  → 离线队列计数器 +1
  
网络恢复（平板检测到网络连接恢复）
  → 横幅变为"正在同步离线数据..."（蓝色）
  → 自动启动上传队列，按时间顺序依次补传
  → 上传中展示队列进度："正在同步 2/5 个会话"
  → 每条上传成功后：
      → 清除该条"待上传"标记
      → 删除该条本地加密文件
      → 云端推送 session_id 至平板（如有延迟则排队处理）
  → 队列全部完成 → 横幅变为"同步完成"（绿色，3 秒后自动消失）

```
**离线数据清除策略：**

| 清除时机 | 条件 | 说明 |
|----------|------|------|
| 上传成功自动清除 | 数据成功上传并收到云端确认 | 即时删除本地加密文件 |
| 手动清除 | 店员在设置中点击"清除离线缓存" | 二次确认后删除所有待上传数据（警告：数据将永久丢失） |
| 过期自动清除 | 离线数据超过 7 天未上传 | 自动清理，避免占用存储空间 |
| 容量超限清除 | 离线队列超过 20 条 | 禁止新离线质检，提示"离线队列已满，请连接网络后重试"；不自动删除已有数据 |
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 离线可用范围 | 外观影像采集 + 硬件审计 + 发票采集可在离线状态完成；OTP 验证（需 SMS）和综合上传（需网络）不可离线 |
| 待上传标记 | 离线期间完成的每条质检数据打上"待上传"标记，包含：session_id（本地预生成）、设备信息摘要、创建时间 |
| 上传顺序 | 恢复网络后严格按时间顺序补传（FIFO），先完成的先上传 |
| 离线队列上限 | 最多缓存 20 条完整质检数据；超出时禁止新质检，提示需联网上传后才能继续 |
| 数据加密 | 离线数据使用 AES-256 加密存储，平板上不可通过文件管理器直接查看或导出 |
| 存储位置 | 平板内部存储的沙盒目录，不暴露在公共存储区域 |
| 成功率保障 | 每条上传最多重试 3 次；仍失败则保留本地，标记"上传失败"，允许手动重试 |
| 后端校验 | 后端记录每台平板的离线缓存次数和上传时间；超过合理频率触发风控告警 |
| 手动清除确认 | 设置中提供"清除离线缓存"入口，操作前弹窗二次确认并警告不可恢复 |
**输入：** 网络状态变化事件 + 质检完成事件
**输出：** 离线队列状态 + 上传队列进度
**验收标准：**
- [ ] 断网状态下质检流程可完整执行（外观采集 + 硬件审计 + 发票采集）
- [ ] 断网时平板顶部持续展示"离线模式"黄色横幅
- [ ] 网络恢复后 5 秒内自动启动上传队列，按时间顺序补传
- [ ] 上传队列展示实时进度："正在同步 N/M 个会话"
- [ ] 每条上传成功后本地加密数据即时删除
- [ ] 离线数据 AES-256 加密存储，不可通过文件管理器直接查看
- [ ] 离线队列满 20 条后禁止新质检，提示"离线队列已满，请连接网络后重试"
- [ ] 离线数据超过 7 天自动清理
- [ ] 设置中提供"清除离线缓存"入口，二次确认后清除
- [ ] OTP 验证和综合上传在离线状态下不可用，明确提示"需要网络连接"

## TAB-P1-02 预约信息加载
**优先级：** P1
**功能描述：**

## TAB-P1-03 拍摄质量实时检测
**优先级：** P1
**功能描述：**
在店员使用平板相机拍摄外观照片时，系统对取景画面进行实时质量检测，包括模糊度、光线亮度、拍摄角度偏差。检测结果以即时视觉反馈形式呈现在取景界面上，引导店员调整拍摄条件。当检测到质量不达标时，主动提示店员调整，避免采集低质量影像影响后续 AI 外观评级和运营审核。
**检测维度与反馈：**

| 检测项 | 判断标准 | 不达标反馈 | 达标反馈 |
|--------|----------|-----------|----------|
| 模糊度 | 拉普拉斯方差算法，阈值可配置；低于阈值判定为模糊 | 取景框变红色边框 + 提示"画面模糊，请保持稳定" | 边框绿色 + 提示"清晰" |
| 光线亮度 | 取景画面平均亮度值；低于阈值判定为光线不足 | 取景框变黄色边框 + 提示"光线不足，请补光或调整角度" + 闪光灯建议 | 边框绿色 |
| 角度偏差 | 与当前角度参考叠加层的偏移量；偏差超过阈值判定 | 叠加层边缘变红 + 方向箭头引导归位 + 提示"请将设备对齐参考线" | 叠加层边缘变绿 + 提示"角度正确" |
| 遮挡检测 | 检测取景画面中设备区域是否被手指或其他物体遮挡 | 遮挡区域高亮红色 + 提示"请勿遮挡设备" | 无提示 |
**交互设计：**

```
取景界面布局（从上到下）：
┌─────────────────────────────────┐
│  [角度名称: 正面屏幕]   [3/10]  │  ← 进度条
│                                 │
│     ┌─────────────────┐         │
│     │                 │         │
│     │   取景画面       │         │  ← 实时检测反馈叠加
│     │   + 参考叠加层   │         │
│     │                 │         │
│     └─────────────────┘         │
│                                 │
│  ⚠ 光线不足，请补光             │  ← 实时提示（动态）
│                                 │
│  [重拍]            [📷 拍照]    │  ← 操作按钮
└─────────────────────────────────┘

```
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 检测频率 | 实时检测，每秒分析 ≥ 10 帧 |
| 模糊阈值 | 默认拉普拉斯方差 < 100 判定为模糊（可后台配置） |
| 低光阈值 | 平均亮度 < 50（0-255）判定为光线不足（可后台配置） |
| 角度偏差阈值 | 水平/垂直偏差 > 15 度或平移 > 画幅 20% 触发引导（可后台配置） |
| 不强制阻止 | 检测不达标时不禁止拍照（避免极端环境无法完成质检），但会红色提示；店员可在确认弹窗中选择"仍要拍摄" |
| 历史反馈 | 拍照后可为每张照片显示质量评分（如"清晰度: 优 / 亮度: 良 / 角度: 优"） |
| 性能要求 | 实时检测不显著增加相机延迟（< 50ms）或耗电 |
**输入：** 相机取景画面（实时视频流）
**输出：** 实时质量检测反馈（叠加层颜色 + 文字提示）+ 照片质量评分
**验收标准：**
- [ ] 取景画面实时展示模糊/亮度/角度检测结果，每秒 ≥ 10 帧
- [ ] 模糊时取景框变红，提示"画面模糊，请保持稳定"
- [ ] 光线不足时取景框变黄，提示"光线不足，请补光"
- [ ] 角度偏差时方向箭头引导归位，提示"请将设备对齐参考线"
- [ ] 三项全部达标时取景框变绿，提示可拍照
- [ ] 质量不达标时仍允许拍照（确认弹窗："当前画面 [模糊/光线不足]，是否仍要拍摄？"）
- [ ] 拍照后在预览界面展示质量评分标签（清晰度/亮度/角度各分三档：优/良/差）
- [ ] 实时检测对相机延迟影响 < 50ms
- [ ] 检测阈值支持后台配置，无需 App 更新即可调整

## TAB-P1-05 外观拒收照片上限
**优先级：** P1
**功能描述：**

|--------|------|

| 必需类型 | 3 张最低要求中必须包含：1 张正面全景、1 张背面全景、至少 1 张损坏细节特写 |

| 数量展示 | 取景界面顶部实时展示"已拍 X/10 张" |
| 删除重拍 | 已拍照片可左滑删除；删除后释放一个配额，可重新拍摄 |
| 超过上限处理 | 不自动删除已有照片，告知店员已达上限 |
| 照片大小 | 每张 ≤ 10MB；超过时自动压缩至 10MB 以下（保持 1080P 分辨率） |
**验收标准：**
- [ ] 拒收照片最少 3 张、最多 10 张
- [ ] 拍摄到 10 张后拍照按钮置灰，提示"已达照片上限（10 张）"
- [ ] 已拍照片可左滑删除，删除后配额恢复
- [ ] 取景界面实时展示"已拍 X/10 张"
- [ ] 不满 3 张时确认按钮置灰，提示"请至少拍摄 3 张损坏照片"
- [ ] 3 张最低要求中缺少必需类型时提示具体缺失项
- [ ] 单张照片 > 10MB 时自动压缩

## P2 增强功能
## TAB-P2-01 门店数据看板
**优先级：** P2
**功能描述：**
平板首页（工作台）展示本门店的回收运营数据概览，以可视化图表形式呈现核心 KPI 指标。支持按日期范围筛选数据，帮助店长和店员了解门店运营状况。
**核心 KPI 指标卡片（顶部横向排列）：**

| 指标 | 计算方式 | 展示格式 |
|------|----------|----------|
| 当日回收台数 | 当日已完成质检的设备数量（不含拒收） | 数字 + "台" |
| 总成交金额 | 当日已核销完成的回收总金额 | ₹XX,XXX（千分位格式化） |
| 拒收率 | 拒收台数 / 总质检台数 × 100% | 百分比 + 趋势箭头（对比昨日） |
| 质检通过率 | 通过台数（未拒收）/ 总质检台数 × 100% | 百分比 + 趋势箭头 |
| 人均质检量 | 当日完成台数 / 当班店员人数 | 数字 + "台/人" |
| 审核调整率 | 被运营调整的台数 / 总上传台数 × 100% | 百分比（越低越好） |
**可视化图表：**

| 图表 | 类型 | 展示内容 |
|------|------|----------|
| 回收量趋势图 | 折线图 / 柱状图（可切换） | 近 7/14/30 天每日回收量趋势 |
| 质检状态分布 | 环形图（Donut Chart） | 当日质检状态分布：已完成 / 已核销 / 已拒收 / 进行中 |
| 拒收原因分布 | 横向条形图 | 近 7/30 天各拒收原因的数量和占比 |
| 品牌回收占比 | 饼图 | 近 7/30 天回收设备品牌分布 Top 5 + "其他" |
| 店员业绩排行 | 条形图 | 当日/近 7 天各店员完成质检数量排行 |
**日期筛选：**

| 筛选项 | 说明 |
|--------|------|
| 今天 | 当日数据（默认） |
| 昨天 | 前一日数据 |
| 最近 7 天 | 滚动 7 日数据 |
| 最近 30 天 | 滚动 30 日数据 |
| 自定义 | 日期区间选择器，最大跨度 90 天 |
**业务规则：**

| 规则项 | 说明 |
|--------|------|
| 数据刷新 | 每 5 分钟自动刷新一次；支持手动下拉刷新 |
| 数据来源 | 从云端运营数据接口拉取，平板不做数据计算 |
| 图表交互 | 图表支持点击交互：点击柱状图柱体查看具体数值 Tooltip；点击饼图扇形高亮并展示占比 |
| 权限控制 | 门店管理员可查看完整看板；普通店员仅可查看回收量和拒收率（不显示店员排行和金额） |
| 离线缓存 | 最近一次成功加载的看板数据缓存至本地，离线时展示缓存数据 + "数据更新于 XX:XX" |
| 空状态 | 当日无数据时展示空状态插图和"今日暂无质检数据" |
| 数据延迟 | 数据 T+0（实时），最大延迟 5 分钟刷新周期 |
**输入：** 门店 ID + 日期筛选条件
**输出：** 可视化数据看板（KPI 卡片 + 图表）
**验收标准：**
- [ ] 顶部展示核心 KPI 指标卡片（回收台数、成交金额、拒收率、通过率、人均量、调整率）
- [ ] KPI 卡片展示对比昨日趋势箭头（上升绿色/下降红色）
- [ ] 支持折线图/柱状图切换查看回收量趋势（近 7/14/30 天）

- [ ] 品牌回收占比以饼图展示 Top 5 + 其他
- [ ] 店员业绩排行以条形图展示
- [ ] 支持日期筛选：今天/昨天/最近 7 天/最近 30 天/自定义（最大 90 天）
