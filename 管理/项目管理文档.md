# Dobara 平台 — 项目管理文档

> 用于项目整体进度跟踪、需求池管理和迭代规划

---

## 一、项目划分

平台拆分为 **4 个子项目**，各自独立开发/测试/迭代：

| 项目编号 | 项目名称 | 技术栈 | 对应 PRD |
|:---:|------|------|------|
| P1 | **Dobara - C端用户 App** | iOS (Swift) + Android (Kotlin) | [02_C端用户App_PRD.md](../模块PRD/02_C端用户App_PRD.md) |
| P2 | **Dobara - 内部业务应用** | 跨端 Flutter / React Native（待定） | [05_内部业务应用_PRD.md](../模块PRD/05_内部业务应用_PRD.md) |
| P3 | **Dobara - 平板质检工具** | Android (Kotlin) 定制 ROM | [01_平板质检工具_PRD.md](../模块PRD/01_平板质检工具_PRD.md) |
| P4 | **Dobara - 云端服务端** | Java/Kotlin (Spring Boot) 或 Go | [06_云端中台_服务端_PRD.md](../模块PRD/06_云端中台_服务端_PRD.md) |

> 原 P5（运营后台）已并入 P2（内部业务应用）：运营后台不再作为独立 Web 端，其管理能力（账号/角色/订单/报表/配置/品类/审核统计）归管理员（SA）角色，上架审核归库管（WH）角色，均在跨端内部业务应用中实现。

### 依赖关系

```
P4 (服务端) ←── 所有端的基础，优先启动
  ├── P3 (平板) ── 依赖服务端 API
  ├── P1 (C端)  ── 依赖服务端 API
  └── P2 (内部业务应用) ── 依赖服务端 API
```

## 二、需求池录入指南

### 2.1 录入来源

需求池数据来源于 [PRD 文档](../模块PRD/) 中各端的功能编号。按 `项目编号-优先级-功能名` 的格式录入：

```
格式：P{项目}-{优先级}-{编号} {功能名}
示例：P4-P0-01 定价引擎
```

## 四、里程碑建议

| 阶段 | 目标 | 涉及项目 | 核心需求 |
|------|------|------|------|
| **M1 — 核心闭环** | 一台旧机从门店回收到商城售出 | P3+P4+P2 | 质检→定价→核销→入库→审核→上架→下单→支付→出库 |
| **M2 — 用户端上线** | C端用户可浏览商城+购买+售后 | P1+P4 | 注册登录、商城、下单、支付、订单、售后 |
| **M3 — 运营管理** | 内部业务应用管理端+多语言+预约 | P2+P4+P1 | 审核、权限、报表、品类、i18n、预约 |
| **M4 — B2B+授信** | 企业批量采购+授信结算 | P2+P4+P1 | B2B 下单、批量锁、子订单拆分、授信、DB 对账 |
| **M5 — 优化完善** | 离线、中断恢复、OTA、评价、对比、盘点 | 全部 | P1/P2 级需求 |
