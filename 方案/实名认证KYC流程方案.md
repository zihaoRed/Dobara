# 实名认证（KYC）流程方案

> 目标：商城交易前对买家完成一次性**实名认证（KYC）**，并**拦截未成年人**（<18 岁），满足印度电商/支付合规要求。

---

## 一、背景与合规要求

- **现状**：用户注册仅「手机号 + OTP」，无实名、无年龄信息。企业账号有 GSTIN（企业 KYC），但个人买家无任何 KYC。
- **合规**：印度电商/支付相关法规要求平台对交易主体做实名认证；且未成年人不具备完全民事行为能力、不能订立买卖合同（Indian Contract Act，成年年龄 18 岁）。具体法条与证件范围**需法务最终确认**（本方案按业界通行做法 Aadhaar/PAN 设计）。
- **目标**：在支付环节前完成一次性实名认证 + 年龄验证；未成年人拦截。

---

## 二、触发时机与位置

- **触发**：支付时——订单确认页点击「提交订单 / 去支付」前检查 KYC。
- **一次性**：首次认证通过后复用，后续交易不再重复；证件到期（Aadhaar 无到期，PAN/护照有）后需更新。
- **拦截**：
  - 未认证 → 引导完成实名认证（弹窗 → KYC 页）。
  - 未成年（年龄 < 18）→ 直接拦截，提示「需年满 18 岁方可交易」。

---

## 三、KYC 内容与验证方式

### 采集字段

| 字段 | 说明 |
|------|------|
| 姓名 | 全名（与证件一致） |
| 出生日期 DOB | 年龄验证（≥ 18） |
| 身份证明 | Aadhaar 号（12 位）/ PAN（10 位）/ 护照 / 驾照 |
| 手机号 | 已 OTP 注册，KYC 时校验与证件关联一致 |

### 验证方式（两档）

| 档位 | 方式 | 说明 |
|------|------|------|
| **快捷档（推荐）** | Aadhaar OTP 实时验证 | 输入 Aadhaar 号 + 关联手机号 → OTP → 服务端调 KYC 服务校验，自动回填姓名 + DOB |
| **备用档** | 证件上传 + 人工审核 | 上传 Aadhaar/PAN/护照/驾照照片 → 管理端人工审核 → 通过/驳回 |

> 快捷档走线上自动化（秒级），备用档兜底无 Aadhaar 或 OTP 校验失败的用户（人工审核，耗时分钟~小时级）。

---

## 四、年龄验证

- 通过 DOB（Aadhaar 回填 / 用户自填 + 证件佐证）校验年龄 ≥ 18。
- **未成年（< 18）→ 拦截交易**，不进入支付；提示「需年满 18 岁」，并提供「联系客服」出口（如有误判）。

---

## 五、状态机

```
[未认证 unverified] → [认证中 pending] → [已认证 verified]（终态，可复用）
                                      └── [认证失败 rejected]（可重新提交）
[已认证 verified] → 证件到期 → [需更新 expired]
```

---

## 六、数据模型 `user_kyc`

```json
{
  "user_id": "UUID",
  "kyc_status": "unverified | pending | verified | rejected | expired",
  "full_name": "string",
  "dob": "YYYY-MM-DD",
  "id_type": "aadhaar | pan | passport | driving_license",
  "id_number_hash": "string (加密存储)",
  "verification_method": "aadhaar_otp | manual_review",
  "verified_at": "ISO8601",
  "reject_reason": "string | null"
}
```

## 七、涉及端与落点

| 端 | 落点 | 改动 |
|----|------|------|
| C端 | 02 PRD | KYC 页（Aadhaar OTP / 证件上传）+ 支付前拦截弹窗 + 认证状态展示 |
| 服务端 | 06 PRD | KYC 验证 API + 年龄校验 + 支付前置校验（未认证/未成年拦截）+ user_kyc 模型 |
| 管理端 | 05 PRD | 备用档证件人工审核（可选，P1） |

---

## 八、待确认的决策点

1. **验证方式**：Aadhaar OTP 为主 + 证件上传兜底（推荐），还是只做 Aadhaar OTP？
2. **企业账号（B2B）**：企业已有 GSTIN，采购员个人是否豁免个人 KYC？还是仍需年龄/身份验证？
3. **证件范围**：仅 Aadhaar，还是 Aadhaar + PAN + 护照/驾照多证件？
4. **拦截范围**：仅拦截商城**购买**，还是换购**回收/预约**也一并要求实名+成年？
5. **优先级**：建议 **P0**（合规红线，且是支付前置）。

> 定下这 5 点后，我按同样流程拆成 PRD 需求（02 C端 / 06 服务端 / 05 管理端）+ UI + 需求池。
