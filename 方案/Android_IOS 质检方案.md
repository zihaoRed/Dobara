# Android/IOS 质检方案

## 1\. 方案目标

使用一台 Android 平板连接待检测手机，完成设备信息读取和九项基础质检。

待检测手机可以是 Android 手机或 iPhone。检测方式分为三类：

- 平板通过 USB 自动读取设备信息。

- 用户在手机网页中完成触控、摄像头、声音等测试。

- 无法自动判断的项目由店员确认。

当前建议使用 Android 平板作为检测主机，不建议使用 iPad。



## 2\. 使用前提

### Android 待检测手机

- 手机已解锁。

- 已开启“开发者选项”和“USB 调试”。

- 首次连接时，用户需要在手机上允许 USB 调试。

### iPhone 待检测手机

- iPhone 已解锁。

- 首次连接时，用户需要点击“信任”并输入锁屏密码。

## 3\. 九项检测内容



检测方式：🤖 USB/ADB 自动读取　🌐 被检手机 H5 检测页　🔀 H5 引导 + 平板 ADB 判定　✍️ 店员确认



> \*\*当前验证状态：\*\*目前只完成了 Android 手机通过 ADB 静默读取信息的初步验证。H5（手机网页）检测与 IMEI 半自动暗码采集的流程方案已定型（见第 5、7、8 节），但触控、传感器、摄像头、扬声器和麦克风等功能尚未经过完整开发和真机验证，暂不能作为已实现能力。主流品牌暗码触发率、IMEI 弹窗截屏可截率、USB 网络共享与 ADB 并存稳定性均需在开发前完成真机验证（验证清单见第 9 节）。
>
>
> \*\*检测通道汇总：\*\*🤖 平板 USB/ADB 自动读取　🌐 被检手机 H5 检测页　🔀 H5 引导 + 平板 ADB 判定　✍️ 店员确认 



|检测项目|检测方式|检测内容|备注与限制|
|---|---|---|---|
|SN / 序列号 / IMEI<br>|🤖 USB 自动读取 + 半自动暗码|Android 按品牌读取对应 SN 字段；IMEI 采用"半自动暗码 + 截屏 OCR"方案（见第 5 节）|不同品牌的字段可能不同，必须记录读取来源；IMEI 识别结果须过 Luhn 校验，失败转人工读屏录入<br>|
|品牌和型号|🤖 USB 自动读取|读取手机提供的品牌、型号和系统版本，再与机型资料库核对|系统返回的可能是内部型号，不一定等于对外销售名称；资料库未匹配时需要人工确认|
|电池情况|🤖 USB 自动读取|读取当前电量、电池状态、循环次数和可用容量信息|各品牌开放的信息不同；无法取得标准健康度时只能显示估算值，不能直接判断电池异常|
|屏幕显示（坏点/烧屏/漏液）|🌐 H5 检测页|H5 全屏循环显示纯色画面（白/红/绿/蓝/黑/灰），店员目视确认显示缺陷|与 AI 外观检测分工：显示类功能缺陷以 H5 现场判定为准，AI 聚焦玻璃/机身/后盖等外观磨损（见 7.2 节）|
|屏幕触控|🌐 H5 检测页|H5 全屏滑涂测试，检查覆盖范围、轨迹连续性和明显断点|只能检测网页能够覆盖的区域，状态栏、系统手势区等位置可能无法完整测试|
|传感器|🌐 H5 检测页|转动或移动手机，检查方向和运动数据是否正常变化|需要用户授权；网页只能检测浏览器支持的传感器，不能保证覆盖手机内的全部传感器|
|存储容量|🤖 USB 自动读取|读取实际总空间、已用空间和可用空间|系统显示容量与商品标称容量的计算方式不同，应分别展示，不能仅凭数值差异判断异常|
|摄像头|🌐 H5 检测页|切换前后摄像头，检查预览和拍照，初步发现黑屏、过暗或明显模糊|受光线、权限和浏览器能力影响；只能做基础检查，不能代替多镜头和成像质量的专业检测|
|扬声器和麦克风|🌐 H5 检测页|播放测试音并录音，检查声音能否正常播放和录入|测试结果会受环境噪声和音量设置影响；失败时无法仅凭网页判断是扬声器还是麦克风问题|
|物理按键|🔀 H5 引导 + 平板 ADB 判定|H5 显示"请按音量+/音量-/电源键"操作引导，平板通过 ADB 监听按键事件自动判定|网页收不到音量/电源键事件，判定必须走 ADB 旁路；结果由平板写入，不由 H5 判定|



网页检测需要用户允许摄像头、麦克风或运动信息权限。用户拒绝授权时，应记录为“未授权”，不能判断为手机硬件损坏。



## 4\. SN 获取方案



Android 手机连接成功后，平板先识别手机品牌，再按以下顺序获取 SN：



1. 有对应品牌规则时，优先读取该品牌的 SN 字段。

2. 品牌字段没有值或未配置品牌规则时，读取 `ro.serialno`。

3. 读取结果为空、明显是占位内容或格式错误时，记录为“无法读取”。



当前品牌规则：



|手机品牌|读取顺序|
|---|---|
|小米 / Redmi|`ro.ril.oem.psno` → `ro.ril.oem.sno` → `gsm.sn` → `gsm.serial`|
|华为 / 荣耀|`ro.huawei.build.version.sn` → `ro.huawei.sn`|
|OPPO / 一加 / realme|`gsm.serial` → `ro.oppo.sn`|
|vivo / iQOO|`ro.vivo.oem.sn` → `persist.sys.vivosn`|
|三星|`ril.serialnumber`|
|其他品牌，包括 PD1|`ro.serialno`|



小米部分手机的 `ro.ril.oem.psno` 会包含 `/`，必须保留完整内容。部分字段可能使用编码保存，程序只有在确认可以正确转换时才使用转换结果，不能盲目转换。



为了保护隐私，操作界面默认只显示 SN 后四位。检测报告应同时记录 SN 来源，方便出现差异时排查。



## 5\. IMEI 获取方案：半自动暗码 + 截屏 OCR

### 5.1 背景：为什么全自动代输不可行



原计划是让平板自动输入 `*#06#`，打开 IMEI 页面后截图识别。真机测试发现，程序虽然能让拨号框显示 `*#06#`，但部分品牌不会弹出设备信息页面，因为程序输入和用户手动输入的处理方式不同。



即使页面成功打开，不同品牌的页面样式也不一样，部分页面还可能不允许截图。OCR 只能识别已经取得的画面，无法解决页面没有弹出的问题。

### 5.2 半自动暗码流程

暗码触发的关键是"最后一个 `#`"由真实按键完成。平板代输前四位，质检员在用户手机上补按最后一位：

1. 平板通过 ADB 打开手机拨号盘。
2. 平板逐键模拟输入 `*` `#` `0` `6`（用 keyevent 逐键发送，不用 `input text`——文本注入路径拨号盘的暗码监听不认）。
3. 平板进入大字引导页："请在手机上按下 # 键"，质检员拿用户手机按下 `#`。
4. 系统识别完整暗码 `*#06#`，弹出 IMEI 信息界面——最后一位由质检员人工按键完成触发，规避"程序输入不触发"的品牌差异。
5. 平板 ADB 截屏（screencap）拉回本地。
6. 端侧 OCR（ML Kit）识别 15 位数字 → Luhn 校验 + 格式校验；双卡机提取 IMEI1 / IMEI2。
7. 识别通过 → 记录（界面默认脱敏只显示后四位）；识别失败 → 重试 1 次 → 仍失败转人工读屏录入（标记"手动录入"）。

### 5.3 容错链与校验

| 层级 | 方式 | 说明 |
|---|---|---|
| ① 优先 | ADB 属性直读 | 部分品牌 getprop 可直接拿到 IMEI 字段，零打扰，命中即跳过暗码 |
| ② 主方案 | 半自动暗码 + 截屏 OCR | 见 5.2 流程 |
| ③ 兜底 | 人工读屏手动录入 | 截屏黑屏（FLAG_SECURE）/ OCR 失败时，质检员照手机屏幕读数录入，标记"手动录入" |



- OCR 不按品牌适配界面区域：全屏识别"15 位连续数字"，天然规避各品牌弹窗样式差异（MIUI 底部面板、三星 Dialog 等）。
- IMEI 是唯一标识且加密入库：识别结果与 ADB 侧线索（getprop 型号、H5 上报的 userAgent）做一致性比对，不一致时黄色警告要求复核。
- iOS 无需暗码：libimobiledevice 可直接读取 IMEI，不走本流程。
- 按键人：暗码最后一位 `#` 统一由质检员拿用户手机按（与整个质检"店员操作、用户在场知情"的口径一致），不由用户自己按。



## 6\. 为什么检测主机选择 Android 平板



现有程序已经可以在 Android 平板上通过 USB 连接 Android 手机，并承载信息读取、网页检测和结果汇总。



如果改用 iPad，现有 USB 连接能力不能直接使用，需要重新开发连接方式，或者增加无线连接、外置采集盒和更多人工步骤。这还会增加兼容测试、设备部署、人员培训和后期维护成本。



因此当前统一使用 Android 平板作为检测主机。这里限制的是检测主机，待检测设备仍然可以是 Android 手机或 iPhone。Android 平板不需要 root 也能完成现有检测。

**6\.1 平板 root 与非 root 的影响**

|对比项|非 root 平板|root 平板|
|---|---|---|
|Android 手机 USB 读取|可以完成|可以完成，读取内容不会因此增加|
|iPhone USB 读取|可以完成|可以完成，读取内容不会因此增加|
|H5 和人工检测|不受影响|不受影响|
|门店部署和管理|USB 授权、程序启动等步骤按系统正常流程操作|可简化部分授权、自动启动、设备管理和问题排查操作|
|安全和维护|系统保持原有安全保护，维护成本较低|系统权限更高，需要额外控制误操作、数据安全和系统升级风险|



能读取哪些信息，主要由待检测手机是否授权以及手机系统是否开放决定。即使检测平板已经 root，也不能绕过待检测手机的限制获取更多 SN、电池或其他数据。



因此，非 root Android 平板可以作为正式方案的基础配置。若门店需要更强的自动启动、设备管理或远程维护能力，可以把 root 作为可选的运维方案，但不应把它当作提升检测能力的必要条件。

## 7\. H5 检测页方案

### 7.1 检测项与判定来源

H5 检测页是被检手机浏览器中打开的标准化检测页面，承担"引导 + 展示 + 能测的项"；网页测不了的项（物理按键）H5 只做操作引导，判定走平板 ADB 旁路。平板始终是主控与结果汇聚方。

| 检测项 | H5 承担 | 判定来源 |
|---|---|---|
| 屏幕显示（坏点/烧屏/漏液/偏色/闪烁） | 全屏循环纯色画面（白/红/绿/蓝/黑/灰） | 店员目视 + H5 确认按钮 |
| 屏幕触控 | 全屏滑涂 Canvas | H5 自动判定（覆盖率/断线） |
| 扬声器 | 播放测试音（左右声道分开） | 店员听感确认 |
| 麦克风 | 录音回放 | 店员听感确认 |
| 摄像头 | 前后摄预览 + 拍照 | H5 基础检测（黑屏/过暗）+ 人工确认 |
| 传感器 | 转动/移动手机 | H5 自动判定（数据变化） |
| 物理按键 | 显示"请按音量+ ×3 / 电源键 ×1"引导 | 平板 ADB 监听按键事件（getevent / dumpsys input） |

### 7.2 与 AI 外观检测的分工（并存，不互相替代）

| 维度 | 判定方 | 理由 |
|---|---|---|
| 屏幕显示类功能缺陷（坏点/烧屏/漏液/偏色/闪烁）与触控 | H5 现场检测 | 相机拍屏幕有摩尔纹/反光干扰，AI 误判率高；纯色画面由屏幕自己发光，判定最准 |
| 屏幕玻璃划痕/碎裂、机身、后盖、接口按键外观 | AI 外观检测（10 张照片 + 360° 视频） | 属于外观磨损，拍照 + AI 判定 |

### 7.3 通信架构与拉起方式

```
平板(主控) ←HTTPS/WS→ 云端中台 ←HTTPS/WS→ 被检手机 H5
                （session_id + 一次性 token 绑定）
```



- Android 拉起：平板通过 ADB 发送 VIEW intent 打开 `https://check.dobara.in/t/{token}`，走系统默认浏览器；门店平板首次部署时把 Chrome 设为默认浏览器。
- iOS 拉起：libimobiledevice 无法远程让 iPhone 打开 URL。iPhone 连平板热点后，用相机扫平板上的二维码进 Safari（相机扫码直达，店员操作成本低）。
- 结果回传：H5 每完成一项，结果实时经云端中转回传平板，平板界面同步点亮该项状态，质检员在平板上看进度，不用盯手机。
- 反作弊：H5 上报 userAgent / 设备内存 / CPU 核心数，与 ADB 读到的机型信息交叉比对，防止店员拿自己手机替检。
- 安全：token 一次性、绑定 session、短有效期；页面资源轻量化（纯色画面用 Canvas 生成，不下载图片，适配印度门店网络）。
- 权限：摄像头/麦克风/运动传感器需浏览器授权；拒绝授权时记录"未授权"，不判为硬件损坏。
- 断网降级：H5 页面部署在云端，门店断网时交互类检测不可用——静态项（ADB 读取、暗码 IMEI）照常，交互项标记"待网络恢复"，走断点续检恢复。本地 HTTP 离线方案因 getUserMedia 强制 HTTPS（自签证书会被浏览器拦截）收益有限，P0 不做。

## 8\. 网络保障：USB 共享与热点

被检手机大多已拔卡或无流量，检测 H5 必须由平板供网：

| 平台 | 方式 | 说明 |
|---|---|---|
| Android | USB 网络共享（主） | 定制平板以 gadget 模式虚拟出 RNDIS/CDC-NCM 网卡，OTG 线连接后手机 host 侧自动识别、DHCP 即插即用，零配置；与 ADB 在同一 USB 连接上并存（多接口 gadget） |
| iOS | 平板 WiFi 热点 + 扫码（唯一可行路径） | iPhone 不识别 RNDIS/CDC-NCM，"平板 USB 给 iPhone 供网"无标准通路；热点 SSID/密码展示在平板引导页，连一次热点 → 扫码 → Safari 打开 |



- 共享的是门店宽带，不耗任何 SIM 流量。
- 流程：USB 连接 → 平台识别 → 自动供网（Android USB 共享 / iOS 热点）→ 平板心跳探测检测页域名可达 → 才进入 H5 检测环节。
- 定制平板固件支持免手动开启 USB 共享时全程无人工网络操作；否则需在平板系统设置中开启一次。

## 9\. 开发前真机验证清单

| # | 验证项 | 覆盖机型 | 通过标准 |
|---|---|---|---|
| 1 | `*#06` 程序代输 + `#` 人工按的暗码触发率 | 小米/Redmi、三星、OPPO、一加、realme、vivo | 主流品牌 ≥ 90% 弹出 IMEI 界面 |
| 2 | IMEI 弹窗截屏可截率 + OCR 识别准确率 | 同上 | 可截率 ≥ 95%，OCR 数字识别 ≥ 98% |
| 3 | USB 网络共享与 ADB 并存稳定性 | 定制平板 + 主流 Android 手机 | 同一 USB 连接下 ADB 与供网互不干扰 |
| 4 | Android 浏览器自动拉起（VIEW intent） | 同上 | 默认浏览器 3 秒内打开检测页 |
| 5 | H5 各项 API 可用性（getUserMedia / DeviceOrientation / Audio） | Chrome（Android）、Safari（iOS） | 检测项全部可执行或有明确降级路径 |
| 6 | iOS 热点 + 扫码流程 | iPhone（iOS 15+） | 扫码到页面打开 ≤ 30 秒 |
