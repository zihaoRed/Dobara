# 预约同步与门店通知方案

> 问题：用户下单预约后，预约单不同步/通知到对应门店；门店只在用户到店核销时才第一次看到订单。
> 目标：预约成功后，预约单**实时同步至门店（店长/店员）**，双端通知，便于门店提前安排接待。

---

## 一、现状数据流（断链在哪）

```
C端预约 → POST /api/sessions → 服务端存 recycle order（appointment_pending + storeId）
                                      │
                                      │ ← 断链：门店侧无人消费这个预约单
                                      ▼
         ├─ 质检工具「待质检」Tab 用的是独立 mock 种子，不是这个预约单
         ├─ 内部业务应用 店老板/店员 没有「预约列表」
         └─ 无任何通知
                                      │
                                      ▼
                   到店 OTP → TAB-P1-02 才加载预约 → 门店第一次看到（被动）
```

---

## 二、目标数据流

```
C端预约 → POST /api/sessions → 预约单（appointment_pending + storeId）
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
            同步到门店列表        通知店长(OWN)       通知店员(CLK)
            (按 storeId)         → 内部业务应用       → 质检工具
                    │             通知中心+未读角标     顶部横幅+通知列表+角标
                    ├─ 质检工具「待质检」Tab
                    └─ 内部业务应用「今日预约」工作台
```

---

## 三、核心设计

### 3.1 数据流打通（预约 → 门店列表）

- 预约单以 `storeId` 为门店维度，创建后即可被该门店的店长/店员查询到。
- **统一数据源**：质检工具「待质检」Tab 与内部业务应用「今日预约」工作台，都从同一个预约单数据源拉取（消除当前质检工具用独立 mock 种子、与 `/api/recycle-orders` 分离的断链）。

### 3.2 双端通知（新预约）

| 项 | 内容 |
|---|---|
| 触发 | 预约创建成功（服务端） |
| 接收方 | **店长（OWN）**→ 内部业务应用；**店员（CLK）**→ 质检工具 |
| 通知模板 | 新增「新预约」（复用 06 PRD CLOUD-P0-15 通知模板规范） |
| 内容 | 用户姓名（脱敏）+ 手机尾号、设备品牌型号、预约日期+时段、服务类型（换购） |
| 质检工具侧 | 复用现有 TAB-P0-06 机制：顶部横幅（5 秒）+ 通知列表持久 + 未读角标 |
| 内部业务应用侧 | 通知中心 + 未读角标 |

### 3.3 门店预约列表

**内部业务应用（店老板/店员）**：新增「今日预约」工作台
- 按时间排序，列出今天待接待的预约。
- 字段：用户、设备、预约日期+时段、服务类型、状态。
- 操作：标记「已到店 / 已开始」；跳转质检（联动质检工具）。

**质检工具**：复用「待质检」Tab（本次已实现），数据源打通即可。

## 四、数据模型

服务端预约单（补充字段）：

```json
{
  "sessionId": "UUID",
  "storeId": "ST-MH-0001",
  "customerName": "脱敏",
  "customerPhone": "98765*****",
  "device": "iPhone 13 128GB",
  "appointmentDate": "2026-09-30",
  "appointmentSlot": "10:00–11:00",
  "serviceType": "trade-in",
  "status": "appointment_pending | arrived | inspecting | ...",
  "createdAt": "ISO8601",
  "notifiedAt": "ISO8601",
  "notifiedTo": ["owner", "clerk"]
}
```

---

## 五、预约状态流转（门店侧）

```
appointment_pending（已预约，待接待）
  → arrived（已到店，OTP 验证通过）
  → inspecting（质检中）
  → completed / rejected / cancelled（复用质检单状态）
```

门店侧可标记「待接待 → 已到店 → 已开始」，用于「提前安排接待」的进度感知。

## 七、已确认决策（定稿）

1. ✅ **通知粒度**：预约创建即推。

3. ✅ **预约列表归属**：内部业务应用「今日预约」+ 质检工具「待质检」两边都有。
4. ✅ **门店标记状态**：需要「已到店 / 已开始」标记。
