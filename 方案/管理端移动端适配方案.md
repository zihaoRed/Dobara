# 管理端（内部业务应用）移动端适配方案

> **版本：** v1.1 | **日期：** 2026-09-07
> **状态：** ✅ P0 已在原型实施完成（Drawer 导航/网格降列/安全区），P1 待做——本文档同时作为复刻蓝本与实施记录
> **适用对象：** 前端开发人员（按本方案对 `UI/apps/management` 原型进行移动端适配复刻）
> **对应 PRD：** `模块PRD/05_内部业务应用_PRD.md`（跨端 App + Web，一套代码）

---

## 1. 背景与目标

PRD 对内部业务应用的核心决策是**跨端开发（一套代码编译 App + Web）**，四角色（SA/OWN/WH/DB）统一登录、按角色显示模块。但当前原型（`UI/apps/management`）主要按桌面 Web 布局构建。

**目标：** 管理端在移动端（Android/iOS 手机浏览器及 WebView，后续可套壳打包 App）达到可用且符合 PRD 交互的体验，供开发人员作为复刻蓝本。

**非目标：**
- 不涉及 C 端 App / 平板质检工具的适配（各有独立原型）
- 不改变既有业务逻辑、路由结构与数据层（`dbStore` / `whStore` / `accountStore` 等不动）
- 不引入新 UI 框架——继续用 Tailwind + `@dobara/ui` + 设计规范 token

## 3. 方案总览：三层适配策略

```
第一层（壳，已完成）：AppShell 移动优先框架
  └── 底部 Tab（模块切换）+ 顶部 Header + max-w-lg 内容限宽
第二层（导航，需补）：模块内子页面导航
  └── 移动端「汉堡菜单 Drawer」承载 Sidebar 的模块内导航（navItems）
第三层（页面，需改）：逐页响应式修正
  └── 网格降列、表格横滑、按钮组折行、触控目标、扫码页移动端行为
```

**断点约定（沿用 Tailwind 默认）：**
- `< 768px`（`md:` 以下）= 移动端布局
- `≥ 768px` = 桌面布局（现状保持）

**核心原则：** 页面组件内不写设备检测（无 `isMobile` state），全部用 Tailwind 响应式 class 表达——一套 DOM，两端渲染，与 PRD「一套代码跨端」决策一致。

## 4. 详细设计

### 4.1 导航：移动端 Drawer（对应 G3，最高优先级）

**现状问题：** 底部 Tab 只覆盖「模块切换」（4 模块 + Settings），模块内子页面导航在移动端不可达。

**方案：** 顶部 Header 左侧加汉堡按钮，点击从左侧滑出 Drawer，内容复用 Sidebar 的 `navItems` 数据结构：

```tsx
// App.tsx AppShell 内新增（示意，开发复刻时按此结构实现）
const [drawerOpen, setDrawerOpen] = useState(false);

// 顶部 Header（md:hidden 部分）：
<header className="md:hidden ...">
  <button onClick={() => setDrawerOpen(true)} aria-label="Menu">
    <Menu size={20} />
  </button>
  <span>Dobara · {moduleMeta[activeModule]?.label}</span>
  ...
</header>

// Drawer（复用 @dobara/ui Modal，left 侧滑样式）：
<Modal open={drawerOpen} onClose={() => setDrawerOpen(false)}>
  {/* 渲染当前模块 navItems（从 Sidebar.tsx 导出 adminNav/ownerNav/whNav/dbNav）*/}
</Modal>
```

**要点：**
1. **导出 navItems**：`Sidebar.tsx` 中 `adminNav/ownerNav/whNav/dbNav` 目前是模块私有，需 `export` 供 Drawer 复用（单一数据源，两端一致）
2. Drawer 内点击导航项 → 关闭 Drawer + navigate（子页面跳转后自动收起）
3. Drawer 底部放「切换角色」入口（复用 Sidebar 的 switch Modal），与 Web 端能力对齐
4. 路由跳转后 Drawer 自动关闭（`useEffect` 监听 `location.pathname`）
5. 现有底部 Tab 保留（模块级切换是高频操作，符合 PRD UA-P0-02 的拇指可达原则）

**交互规范：**
- Drawer 宽度 `w-[280px]`，遮罩点击关闭，右侧滑动手势关闭（P1 可加）
- 打开时 Body 滚动锁定

### 4.2 网格降列规则（对应 G1）

统一处理模式——**移动端降列，`md:` 恢复桌面列数**：

| 现状 | 改法 | 适用 |
|------|------|------|
| `grid-cols-4` | `grid-cols-2 md:grid-cols-4` | KPI 卡、九宫格 |
| `grid-cols-3` | `grid-cols-2 md:grid-cols-3`（数据卡）或 `grid-cols-3` 保留（九宫格图标列） | 见逐页清单 |
| `grid-cols-2` | 保持（2 列在 360px 屏可用） | 多数 |

**逐页清单（12 处裸多列网格）：**

| 页面 | 行 | 现状 | 目标 |
|------|-----|------|------|
| AccountMgmt | 585 | `grid-cols-3` | `grid-cols-2 md:grid-cols-3` |
| MallOrderDetail | 150 | `grid-cols-3` | `grid-cols-1 sm:grid-cols-3`（金额摘要改为纵向堆叠） |
| RecycleOrderDetail | 82 | `grid-cols-3` | `grid-cols-1 sm:grid-cols-3` |
| Reports | 111 | `grid-cols-4` | `grid-cols-2 md:grid-cols-4` |

| ReconciliationDetail | 53 | `grid-cols-3` | 保持 `grid-cols-3`（三金额卡紧凑）或 `grid-cols-1 sm:grid-cols-3` |
| BatchOutbound | 253 | `grid-cols-3` | 保持（进度计数小格） |

### 4.4 触控与安全区（G4/G5/G7）

| 项 | 规范 |
|---|---|
| 触控目标 | 所有可点击元素移动端最小 44×44px——文本链接加 `py-2`、小按钮用 `size="lg"` 或补 `min-h-[44px]` |
| 按钮组 | 横排按钮组统一 `flex flex-wrap gap-2`；底部固定操作条（如结算确认）移动端吸底（`sticky bottom-[56px]` 避开底部 Tab） |
| 安全区 | AppShell 底部导航加 `pb-[env(safe-area-inset-bottom)]`；`pb-14` 改为 `pb-[calc(3.5rem+env(safe-area-inset-bottom))]` |
| 输入框 | `font-size ≥ 16px`（iOS 聚焦不自动放大）——既有 `text-body` token 即为 16px，新页面遵守 |
| 弹窗 | Modal 移动端全宽底部抽屉化（`bottom sheet`）为 P1 优化项 |

### 4.5 扫码页移动端行为（G6，需交付说明）

原型用输入框模拟扫码，真实移动端需区分：

| 场景 | 方案 |
|------|------|
| Web 原型（演示） | 维持输入框 + Enter 提交（现状） |
| 移动端 App（复刻目标） | 调用相机扫码（Capacitor/原生相机 + JSBarcode 扫码 SDK）或扫码枪蓝牙 HID 键盘模拟输入 |
| 交互 | 扫码后自动提交（无需点按钮），失败震动 + 红色提示，连续扫码模式（PRD WH-P0-01「入库完一台自动回到扫码页」） |

**复刻注意：** PRD 的「摄像头扫描」在 App 端是原生能力，Web 原型仅模拟交互流程；开发按目标平台选择实现方式，页面流程/校验逻辑保持与原型一致。

### 4.6 Web 端窄窗口（非手机但常见）

Web 端浏览器窗口缩到 <768px 时自动切换移动布局——**不额外处理**，响应式 class 自然生效（Tailwind media query 按视口宽度）。

## 6. 交付说明（给开发人员）

1. **复刻基线**：以 `UI/apps/management` 当前 master 为基线（含 WH 库位录入 + DB 模块闭环）。
2. **设计 token**：所有颜色/字号/间距/圆角使用 `UI/印度Dobara-设计规范文档.md` 的 token，不得硬编码——设计规范文档中 token 已在 Tailwind config 落地，开发直接用 class 即可。
3. **组件**：优先使用 `@dobara/ui` 既有组件（Card/Button/Input/Badge/Modal），缺什么补什么（如 Drawer），补的组件进 `UI/packages/shared-ui` 供各端复用。
4. **响应式约定**：组件内不写 `isMobile` 之类设备检测，全部 Tailwind 响应式 class（一套 DOM 跨端，对应 PRD 决策）。
5. **验证**：每页改完跑 `npx tsc --noEmit`；UI 检查用 DevTools 360×800 视口过一遍 §5 验证清单。
6. **扫码能力**：Web 原型仅模拟；App 端实现方案见 §4.5，复刻时按目标平台选型。
7. **后续 App 化**：P0/P1 完成后，Web 代码可直接套 Capacitor/WebView 壳打包（跨端决策的落地路径），无需重写。
