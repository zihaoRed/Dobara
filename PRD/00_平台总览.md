## 一、平台架构（4 个前端 + 1 中台）

```
                    ┌──────────────────────────┐
                    │   云端中台 (服务端 API)     │
                    │   定价引擎 · 状态机 · 库存   │
                    │   支付 · 路由 · 核销 · OTP  │
                    │   预约 · 授信 · i18n       │
                    └──────┬──────┬────────────┘
                           │      │
        ┌──────────────────┼──────┼──────────────────┐
        │                  │      │                  │
   ┌────▼────┐      ┌──────▼──────┐      ┌────▼────┐
   │ 用户端   │      │内部业务应用   │      │平板质检  │
   │ C-end   │      │Internal Biz │      │Tablet   │
   │ iOS/And │      │App + Web   │      │Android  │
   └─────────┘      └─────────────┘      └─────────┘

```

| 端 | 仓库名 | 平台 | 使用者 | 核心职责 |
|------|------|------|------|------|
| 用户端 Consumer | `dobara-consumer` | iOS + Android App / H5 | 消费者 + 企业采购 | 换购预约、质检报告、商城浏览购买、订单追踪、B2B 采购 |
| 内部业务应用 Internal Business App | `dobara-work` | 跨端（App + Web，一套代码） | 管理员 / 店老板 / 库管 / DB | 按角色权限显示模块：<br>**管理员**→组织/账号/角色/订单/报表/配置/品类/审核统计<br>**店老板**→核销录入、店员管理、营收<br>**库管**→入库、翻新、上架审核、出库、盘点<br>**DB**→授信结算、对账、凭证审核、佣金 |
| 平板质检 Tablet | `dobara-inspection` | Android 定制平板 | 门店店员 | 外观拍照、硬件审计、外观点检、核销状态同步 |
| 云端中台 Backend | `dobara-server` | Server API | 系统 | 定价引擎、状态机、库存、支付、路由、核销、OTP、i18n |

## 二、核心业务流程

```
线上预约(1) → 到店 OTP 验证(2) → 外观采集(3-4) → 外观拒收判断(5)
  → 硬件审计(6-7) → 发票采集(8) → 数据上传(9) → 定价+报告推送(10-11)
  → 用户接受报价(12-13) → 店老板录入售价(14-15) → 用户新机确认核销(16-17)
  → DB 发旧机到仓库(18-19) → 入库确认(20) → 翻新判断(21-22)
  → 库管审核+上架(23-25) → C端浏览购买(26-31) → 仓库发货

```

## 三、状态机总览

```
[质检完成] ──(用户接受+核销)──→ [待上架申请] ──(库管审核)──→ [在库可售]
                                                                    │
                                                               (用户下单)
                                                                    ↓
                                                               [付款中]
                                                                    │
                                                    ┌─(支付成功)──→ [已售]
                                                    │                │
                                                    │           (仓库出库)
                                                    │                ↓
                                                    │           [已发货]
                                                    │
                                                    └─(超时)──→ [在库可售]

```
终端状态：[已完成-拒收]（外观拒收）、[已发货]（售出完成）

## 四、角色与权限

### 4.1 六个角色（一套账号体系）

| 角色编码 | 角色 | 绑定实体 | 所属端 |
|------|------|------|------|
| `ROLE-SA` | 系统管理员（含原运营能力） | 无（全局） | 内部业务应用（跨端） |
| `ROLE-OWN` | 店老板 | 门店 | 内部业务应用（跨端） |
| `ROLE-WH` | 库管 | 仓库 | 内部业务应用（跨端） |
| `ROLE-DB` | 财务/结算 | 无（跨门店） | 内部业务应用（跨端） |
| `ROLE-CLK` | 店员/质检员 | 门店 | 平板质检工具 |
| `ROLE-ENT` | 企业采购员 | 无 | C 端 App |

### 4.2 角色权限矩阵

| 功能 | 用户端 | 内部业务应用 | 平板 |
|------|:---:|:---:|:---:|
| 换购预约 + 报告 + 报价 | ✓ | — | — |
| 商城浏览 + 下单 | ✓ | ✓ (B2B) | — |
| 核销价格录入 + 店员管理 + 营收 | — | ✓ (店老板) | — |
| 入库 / 出库 / 翻新 / 盘点 | — | ✓ (库管) | — |
| **上架审核** | — | ✓ (库管) | — |
| 授信结算 + 对账 + 凭证审核 + 佣金 | — | ✓ (DB) | — |
| 订单管理 + 报表 + 配置 + 品类 | — | ✓ (管理员) | — |
| 账号 / 角色 / 权限管理 | — | ✓ (管理员) | — |
| 质检（外观 + 硬件） | — | — | ✓ (店员) |
